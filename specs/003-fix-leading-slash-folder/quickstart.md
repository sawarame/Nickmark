# クイックスタート検証ガイド (Quickstart Validation Guide): 先頭スラッシュ付きフォルダ指定の正規化と認識バグ修正

**機能ブランチ**: `003-fix-leading-slash-folder`  
**日付**: 2026-11-09  
**対象**: 先頭スラッシュ・連続スラッシュを含む登録・検索・フォルダ絞り込みのエンドツーエンド検証手順

---

## 前提条件とビルド手順

1. **ビルドの実行**:
   ```bash
   npm run build
   ```
2. **拡張機能の再読み込み**:
   - Google Chrome で `chrome://extensions/` を開き、Nickmark の更新（リロード）ボタンをクリックする。

---

## 検証シナリオ

### シナリオ 1: 先頭スラッシュ付き登録の正規化と管理画面でのフォルダ絞り込み (User Story 1 & 3)
1. 管理画面（`nm :ls`）またはポップアップ（`Option + Shift + D`）を開く。
2. ニックネームに `/work/gh`、URL に `https://github.com` を入力して登録する。
3. 続けてニックネームに `//work//search/`、URL に `https://google.com` を入力して登録する。
4. 管理画面上部の「フォルダ」ドロップダウンを開く。
5. **期待される結果**:
   - 登録されたニックネームが `work/gh` および `work/search` に自動正規化されている。
   - フォルダドロップダウンに空のフォルダ（`📁  (...)`）が存在せず、`📁 work (2)` が表示される。
   - `📁 work (2)` を選択すると、`work/gh` と `work/search` の 2 件が正しく一覧テーブルに絞り込み表示される。

### シナリオ 2: オムニボックスでの先頭スラッシュ付きフォルダ検索・一括オープン (User Story 2)
1. アドレスバーで `nm /work/` と入力する。
2. **期待される結果**:
   - 最上位（デフォルト）候補に `work/` フォルダの一括オープン案内（2タブ）が表示され、Enter を押すと 2 つのタブがバックグラウンドで開く。
3. アドレスバーで `nm /work` または `nm /work/gh` と入力する。
4. **期待される結果**:
   - `work/` の一括オープン候補および `work/gh` の個別候補が正常にサジェストされる。
5. アドレスバーで `nm :open /work`（または `nm :open /work/`）と入力する。
6. **期待される結果**:
   - サジェスト候補に `📁 work/ (2 tabs)` が表示され、Enter で配下の URL が一括オープンされる。

### シナリオ 3: オートコンプリートでの先頭スラッシュ対応と異常値ガード (User Story 3 & Edge Cases)
1. ポップアップまたは管理画面のニックネーム欄に `/wo` と入力する。
2. **期待される結果**:
   - `work/` や `work/gh` が自動補完候補として表示される。
3. ニックネーム欄に `/` または `///` のみを入力して登録ボタンを押す。
4. **期待される結果**:
   - 空のニックネームとして扱われ、必須入力エラーメッセージが表示されて不正データの登録が防止される。
