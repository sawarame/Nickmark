# 機能仕様書: 先頭スラッシュ付きフォルダ指定の正規化と認識バグ修正 (Leading Slash Folder Normalization & Filtering Fix)

**Feature Branch**: `003-fix-leading-slash-folder`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "先頭にスラッシュを入れるとフォルダで絞り込んだときに認識されないバグを修正したいです。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 先頭スラッシュを含むニックネームのフォルダ絞り込みと管理 (Priority: P1)

ユーザーが `/work/gh` のように先頭にスラッシュを付けてニックネームを登録した場合や、既にそのようなデータが保存されている場合でも、空文字の親フォルダが誤って生成されることなく `work` フォルダとして正しく認識され、管理画面のフォルダ絞り込みフィルタや一括操作（一括オープン・リネーム・削除）が正常に機能する。

**Why this priority**: ユーザーが直面している「先頭にスラッシュを入れるとフォルダで絞り込んだときに認識されない」という直接のバグを解消し、管理画面でのフォルダ絞り込みと管理を確実に機能させるため。

**Independent Test**: `/work/gh` のように先頭スラッシュ付きでブックマークを登録（または既存データとして保持）した状態で管理画面を開き、フォルダ一覧に空のフォルダ（`📁  (...)`）が表示されず `📁 work` として表示され、`work` で絞り込んだ際に該当ブックマークが一覧に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 先頭にスラッシュを含むニックネーム（例: `/work/gh`）が登録されている、または新規に入力された状態、**When** 管理画面のフォルダ絞り込みドロップダウンを開く、**Then** 空文字のフォルダ項目は生成されず、`work` フォルダとして集約・認識される。
2. **Given** フォルダ絞り込みドロップダウンで `work` フォルダを選択した状態、**When** ブックマーク一覧テーブルを表示する、**Then** 先頭スラッシュの有無にかかわらず `work` フォルダ配下のすべてのブックマークが漏れなく絞り込み表示される。
3. **Given** フォルダ絞り込みドロップダウンで「未分類（ルート）」を選択した状態、**When** `/gh` のように先頭にのみスラッシュがあり階層を持たないデータが存在する、**Then** フォルダ階層を持たないルート項目として正しく分類・表示される。
4. **Given** 管理画面で特定のフォルダ（例: `work`）を選択した状態、**When** フォルダの一括オープン、フォルダ名変更（リネーム）、またはフォルダ一括削除を実行する、**Then** 先頭スラッシュの有無に影響されず、対象フォルダ配下の全ブックマークに対して一括操作が正常に完了する。

---

### User Story 2 - アドレスバー（オムニボックス）での先頭スラッシュ付きフォルダ検索・一括オープン (Priority: P1)

ユーザーがアドレスバー（オムニボックス）でブックマークを検索またはフォルダ一括オープンする際に、`/work/` や `/work` のように先頭にスラッシュを入力した場合でも、`work/` や `work` と入力したときと全く同様に該当フォルダおよびブックマークが認識され、候補表示と遷移・一括オープンが行える。

**Why this priority**: キーボード操作特化の Nickmark において、アドレスバーからの検索・絞り込み時に先頭スラッシュを入力してしまうケースでも、意図通りフォルダやブックマークが認識されることが体験の一貫性に不可欠であるため。

**Independent Test**: `work/gh` が登録されている状態で、アドレスバーに `nm /work/` または `nm /work` と入力し、フォルダ一括オープン候補および `work/gh` の候補が表示され、Enter キーで正常に開けることを確認する。

**Acceptance Scenarios**:

1. **Given** フォルダ `work` 配下にブックマーク（例: `work/gh`, `work/jira`）が登録されている状態、**When** アドレスバーで `nm /work/` と先頭スラッシュ付きで入力する、**Then** 最上位（デフォルト）候補として `work` フォルダの一括オープン候補が表示され、Enter キーで配下の全 URL が開く。
2. **Given** フォルダ `work` 配下にブックマークが登録されている状態、**When** アドレスバーで `nm /work` または `nm /work/gh` と入力する、**Then** 先頭スラッシュを除いた `work` や `work/gh` に対して前方一致・完全一致として認識され、フォルダ一括オープン候補および個別ブックマーク候補が正しく表示される。
3. **Given** フォルダ `work` 配下にブックマークが登録されている状態、**When** コマンドモードで `nm :open /work` または `nm :open /work/` と入力する、**Then** 入力途中のサジェスト候補に `work/` フォルダが表示され、実行すると配下のブックマークが一括オープンされる。

### User Story 3 - 登録・編集時のニックネームパス正規化と入力補完 (Priority: P2)

ユーザーが新規登録（管理画面・ポップアップ・`:add` / `:addall` コマンド）や編集、フォルダ名変更、JSON エディタ保存を行う際、先頭・末尾の余分なスラッシュや連続するスラッシュが自動的に正規化（例: `/work/gh` → `work/gh`）されて保存される。また、入力欄で `/wo` のように先頭スラッシュ付きで入力しても、フォルダやニックネームの自動補完候補が正常に提示される。

**Why this priority**: 新規登録や編集の入り口でパスの表記ゆれ（先頭スラッシュ等）を正規化しておくことで、不整合データの発生を未然に防ぎ、どの画面・コマンドからも一貫したフォルダ管理を実現するため。

**Independent Test**: ポップアップまたは管理画面からニックネーム `/work/test` でブックマークを登録し、保存されたニックネームが `work/test` に正規化されていること、および入力中に `/w` と打っても `work/` が補完候補に出ることを確認する。

**Acceptance Scenarios**:

1. **Given** 管理画面、ポップアップ、またはオムニボックスの `:add` / `:addall` コマンドでブックマークを登録・編集する際、**When** ニックネームに `/work/gh` や `//work//gh/` のように先頭・末尾・連続スラッシュを含めて保存する、**Then** `work/gh` のように正規化された形式で保存される。
2. **Given** フォルダ `work/` が存在する状態、**When** 管理画面またはポップアップのニックネーム入力欄に `/wo` と入力する、**Then** 先頭スラッシュを無視して `work/` および `work/` 配下の既存ニックネームが補完サジェストに表示される。

---

### Edge Cases

- **スラッシュのみの入力**: ニックネームやフォルダ名として `/` や `///` のようにスラッシュのみが入力された場合、正規化後は空文字となるため、有効なニックネーム・フォルダ名としては扱わず、必須入力エラーまたは検索クエリなしとして安全に処理する。
- **連続スラッシュを含むパス**: `work//sub///item` のように中間に連続するスラッシュが含まれる場合も、単一のスラッシュ `work/sub/item` として扱い、空の中間フォルダが生成されないようにする。
- **既存ストレージ内の未正規化データとの互換性**: アップデート前に既に `/work/gh` のようなキーでストレージに保存されているブックマークが存在する場合でも、ユーザーが手動で再保存する前から、フォルダ抽出・管理画面のフォルダ絞り込み・オムニボックス検索・一括操作（オープン・リネーム・削除）のすべてにおいて `work/gh` と同等に認識・処理される。
- **同じ正規化パスへの統合**: 既存データや JSON 編集において、万が一 `/work/gh` と `work/gh` の両方が存在していた場合でも、同一 URL の重複登録を防ぎつつ安全に統合・処理される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはニックネームおよびフォルダパスを解釈する際、先頭および末尾のスラッシュ（`/`）を除去し、連続する複数のスラッシュを単一のスラッシュにまとめる正規化を行わなければならない（MUST）。
- **FR-002**: フォルダ抽出処理は、先頭にスラッシュを含むニックネーム（例: `/work/gh`）から空文字（`""`）のフォルダを生成してはならず、有効なフォルダ名（例: `work`）のみを抽出しなければならない（MUST）。
- **FR-003**: 管理画面のフォルダ絞り込み（「すべてのフォルダ」「未分類（ルート）」および個別フォルダ選択）は、正規化されたニックネームパスに基づいて判定し、先頭スラッシュを含む既存データであっても選択したフォルダで漏れなく絞り込み表示できなければならない（MUST）。
- **FR-004**: オムニボックスの通常検索・フォルダ一括オープン・コマンドモード（`:open`, `:rm`, `:add`, `:addall`）は、検索キーワードや引数に先頭スラッシュが含まれている場合でも、正規化したパスに基づいてフォルダおよびニックネームを照合・サジェスト・実行できなければならない（MUST）。
- **FR-005**: 管理画面（新規追加・編集・JSON編集）、ポップアップ登録、およびオムニボックス（`:add`, `:addall`）でブックマークを保存する際、ニックネームの先頭・末尾・連続スラッシュを正規化した上で保存しなければならない（MUST）。
- **FR-006**: 管理画面およびポップアップのニックネーム自動補完（オートコンプリート）は、入力クエリの先頭にスラッシュが含まれている場合でも、該当するフォルダプレフィックスおよびニックネームを候補として提示しなければならない（MUST）。
- **FR-007**: フォルダの一括操作（一括オープン、フォルダ名リネーム、フォルダ一括削除）は、先頭スラッシュの有無にかかわらず対象フォルダに属するすべてのブックマークに対して一貫して適用されなければならない（MUST）。

### Key Entities *(include if feature involves data)*

- **ニックネームパス (Nickname Path)**: ブックマークに紐づく識別名。スラッシュ（`/`）を含むことで階層的なフォルダ構造を表現する。正規化後は先頭・末尾にスラッシュを持たず、空の階層セグメントを含まない形式（例: `work/gh`, `infra/aws/prod`）となる。
- **フォルダ (Folder)**: ニックネームパス内の最後のスラッシュより前の階層から動的に導出されるグループ単位（例: `work`, `infra`, `infra/aws`）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 先頭にスラッシュを付けて登録されたブックマーク、または先頭にスラッシュを付けて入力されたフォルダ検索・絞り込み操作の 100% において、スラッシュなしの場合と同一のフォルダおよびブックマークが認識・表示される。
- **SC-002**: 管理画面のフォルダ選択肢において、先頭スラッシュや連続スラッシュに起因する空文字フォルダ（名前のないフォルダ項目）の発生件数が 0 件になる。
- **SC-003**: すべての登録・編集経路（管理画面、ポップアップ、オムニボックスコマンド、JSON編集）を通じて保存されるニックネームの 100% が、先頭・末尾・連続スラッシュを含まない正規化された形式で保存される。

## Assumptions

- ニックネームにおけるスラッシュ（`/`）は常にフォルダ階層の区切り文字として使用されており、先頭や末尾のスラッシュに特別な別意味（ルートディレクトリとの区別など）を持たせる必要はなく、同一のフォルダ階層として統一的に扱うことがユーザーの期待に合致している。
- 既存のブックマークデータに先頭スラッシュ付きのニックネームが含まれている場合、読み込み時または操作時に正規化することで、データ損失なく既存のブックマーク資産をそのまま利用できる。
