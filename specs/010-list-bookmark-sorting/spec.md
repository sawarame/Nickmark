# Feature Specification: ブックマーク一覧の並び替え機能

**Feature Branch**: `011-list-bookmark-sorting`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "https://github.com/sawarame/Nickmark/issues/18 こちらの機能を実装したいです。詳細や不明点確認することがあれば聞いてください。" (GitHub Issue #18: 「ブックマーク一覧に下記項目での並び替え機能をつける - 最終使用日時 - スコア」)

**Clarifications Applied**:
- **Q1 (操作 UI 形態)**: 既存の固定幅テーブル（5 列構成）を維持し、ツールバー（フォルダ絞り込みバー付近）に「並び替え」セレクト（ドロップダウン）を配置する（B）。
- **Q2 (初期表示と状態保持)**: 初回（未設定時）の初期表示は従来通り（デフォルト順）とし、ユーザーが変更した並び替え条件は端末固有のローカル設定として保存し次回以降も保持する（C）。
- **Q3 (ピン留めの扱い)**: 最終使用日時・スコアで並び替える際はピン留め状態に関わらず、純粋に指定項目の値のみで並び替える（A）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 最終使用日時によるブックマーク一覧の並び替え (Priority: P1)

ユーザーはブックマーク管理画面の一覧を見る際、最近アクセスしたブックマークをすぐに見つけたり、逆に長期間使っていない不要なブックマークを洗い出して整理したりするため、ツールバーの並び替え選択から一覧を「最終使用日時」の降順（新しい順）・昇順（古い順）で並び替えたい。

**Why this priority**: ブックマークの利用状況を把握して整理（棚卸し）する上で、「いつ最後に使ったか」で並び替えられることは最も直接的かつ汎用的なニーズであり、単体でも高い実用価値を持つため。

**Independent Test**: 異なる最終使用日時を持つ複数のブックマークが登録された状態で管理画面を開き、ツールバーの並び替えセレクトから「最終使用日時（新しい順）」および「最終使用日時（古い順）」を選択して、表示順とページング全体が正しく最終使用日時の順に並び替わることを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 最終使用日時が異なる複数のブックマークが登録されている管理画面の一覧、**When** ユーザーがツールバーの並び替えセレクトから「最終使用日時（新しい順）」または「最終使用日時（古い順）」を選択する、**Then** すべての表示対象ブックマークが最終使用日時の新しい順または古い順に正しく並び替わって表示される。
2. **Given** フォルダ絞り込みが適用されている一覧、**When** ユーザーが「最終使用日時」で並び替える、**Then** 絞り込まれたフォルダ内のブックマークのみを対象に最終使用日時順で並び替わる。
3. **Given** ページングで複数ページに分かれる件数のブックマークが登録されている状態、**When** ユーザーが「最終使用日時」で並び替える、**Then** 現在のページ内だけでなく全件を対象に並び替えが行われた上で表示される。

---

### User Story 2 - スコアによるブックマーク一覧の並び替え (Priority: P1)

ユーザーは自身の利用頻度と直近性を反映した「スコア」の高いブックマークや、ほとんど使われておらずスコアが低いままのブックマークを管理画面で確認・整理するため、ツールバーの並び替え選択から一覧を「スコア」の降順（高い順）・昇順（低い順）で並び替えたい。

**Why this priority**: Nickmark は指数減衰スコアによってサジェスト順位を最適化しているため、ユーザーがそのスコア基準で一覧を確認・整理できることは、Issue #18 で明示されたもう一つの必須要件であるため。

**Independent Test**: 異なるスコア値を持つ複数のブックマークが登録された状態で管理画面を開き、ツールバーの並び替えセレクトから「スコア（高い順）」および「スコア（低い順）」を選択して、表示順がスコア数値の大小通りに並び替わることを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 異なるスコア値を持つ複数のブックマークが登録されている管理画面の一覧、**When** ユーザーがツールバーの並び替えセレクトから「スコア（高い順）」または「スコア（低い順）」を選択する、**Then** すべての表示対象ブックマークがスコアの高い順または低い順に正しく数値比較で並び替わって表示される。
2. **Given** 小数を含むスコア（例: `1.5` と `10.2`）が混在する一覧、**When** ユーザーが「スコア」で並び替える、**Then** 文字列順ではなく数値の大小として正しく比較され、`10.2` が `1.5` より大きい値として扱われる。

---

### User Story 3 - 既存テーブルの視認性維持・選択状態の永続化・純粋値ソート (Priority: P2)

ユーザーは既存のすっきりした固定幅テーブル（5 列構成）を保ったまま並び替えを操作でき、一度選んだ並び替え条件を次回管理画面を開いたときにも引き継ぎたい。また、並び替え時はピン留めの有無に左右されず純粋に選択項目の値順で確認したい。

**Why this priority**: 一覧テーブルの固定幅レイアウトを崩さずに新機能を提供し、再訪問時の再設定の手間を省きつつ、既存機能（列ヘッダーソート・ピン留め・インライン編集）と矛盾なく共存させることが日常的な操作性を高めるため。

**Independent Test**: 管理画面で既存の 5 列構成が変わっていないこと、並び替え選択が画面の再読み込み後も保持されること、ピン留め済みと未ピン留めのブックマークが混在しても純粋に最終使用日時またはスコアの値のみで並ぶことを検証できる。

**Acceptance Scenarios**:

1. **Given** 並び替え条件を一度も変更していない初期状態、**When** ユーザーが管理画面を初めて開く、**Then** 一覧は従来のデフォルト順で表示され、ツールバーの並び替えセレクトも「デフォルト順」が選択されている。
2. **Given** ユーザーがツールバーから「最終使用日時（新しい順）」などの並び替え条件を選択した状態、**When** 管理画面のタブを閉じて再度開き直す（またはページを再読み込みする）、**Then** 前回選択した並び替え条件が復元され、その順序で一覧が表示される。
3. **Given** ピン留めされたブックマークとピン留めされていないブックマークが混在する一覧、**When** ユーザーが最終使用日時またはスコアで並び替えを選択する、**Then** ピン留めの有無を優先せず、純粋にすべての行が最終使用日時またはスコアの値の大小のみで並び替わる。
4. **Given** 一覧が最終使用日時またはスコアで並び替えられている状態、**When** ユーザーがブックマークのインライン編集・ピン留め切替・新規追加・削除・他タブからのフォーカス復帰による自動再更新を行う、**Then** 現在選択中の並び替え条件が維持されたまま最新データで再描画される。

---

### Edge Cases

- **最終使用日時やスコアが未設定・同値の場合**: 既存データや手動インポート等で最終使用日時が未設定（または `0`）や同一値・同スコアのエントリが存在する場合でもエラーにならず、決定的な補助順（ニックネーム昇順・URL 昇順等）で安定して並び替わること。
- **ツールバーの並び替えと既存テーブル列ソートの競合防止**: ユーザーがツールバーのセレクトで並び替えを変更した際はテーブル列ヘッダーのソート状態を解除して選択条件を適用し、逆に既存の列ヘッダー（ニックネーム／タイトル／URL）をクリックして並び替えた場合はツールバーの表示・適用状態と矛盾しないよう、列ヘッダーソート側が機能しつつ次回保存状態と不整合を起こさないようにすること。
- **インライン編集中の並び順変動防止**: ユーザーが最終使用日時やスコア順で表示中にニックネーム・タイトル・URL をインライン編集している最中、フォーカス復帰等で自動再読込が発生しても編集中セルが閉じたり入力内容が失われたりしないこと。
- **新しいブックマーク追加直後の位置**: 最終使用日時またはスコアの降順表示中に新規ブックマーク（初期スコア `1.0`、最終使用日時＝登録時刻）を追加した場合、追加後の状態に応じて一覧内の適切な位置へ即座に反映されること。
- **狭い画面幅でのツールバー折り返し**: フォルダ絞り込みバーに並び替えセレクトを追加しても、狭い画面幅では自然に折り返され、テーブルや操作ボタンと重なったりレイアウトが崩れたりしないこと。
- **不正・未知の保存済み並び替え設定値**: ローカル設定に未知の文字列や破損した値が保存されていた場合でも、エラーを起こさず安全に「デフォルト順」へフォールバックすること。
- **多言語表示**: 並び替えラベルおよび選択肢名（デフォルト順、最終使用日時 新しい順／古い順、スコア 高い順／低い順）が日本語／英語の表示言語設定に応じて即座に切り替わること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理画面のブックマーク一覧は、各ブックマークが保持する「最終使用日時」を基準に降順（新しい順）および昇順（古い順）で並び替えできなければならない。
- **FR-002**: 管理画面のブックマーク一覧は、各ブックマークが保持する「スコア」を基準に数値大小として降順（高い順）および昇順（低い順）で並び替えできなければならない。
- **FR-003**: 並び替えの操作手段は、一覧テーブルの既存の 5 列構成（ニックネーム、タイトル、URL、ピン留め、操作）を増やさず、一覧上部のツールバー（フォルダ絞り込みバー付近）に「並び替え」セレクト（ドロップダウン）を配置して提供しなければならない。選択肢には少なくとも「デフォルト順」「最終使用日時（新しい順）」「最終使用日時（古い順）」「スコア（高い順）」「スコア（低い順）」を含めなければならない。
- **FR-004**: 並び替え条件が未保存の初回表示時は従来通りの「デフォルト順」で一覧を表示し、ユーザーがツールバーから並び替え条件を変更した際はその選択状態を端末固有のローカル設定として保存し、次回管理画面を開いた際も保持された並び替え条件を自動適用しなければならない。保存値が無効な場合は安全に「デフォルト順」へフォールバックしなければならない。
- **FR-005**: 最終使用日時またはスコアで並び替えを実行する際は、ブックマークのピン留め状態によるグループ優先を行わず、純粋に指定された項目の値のみで一覧全体を並び替えなければならない。
- **FR-006**: ツールバーでの並び替えは、フォルダ絞り込みが選択されている場合は絞り込み結果の全件に対して適用され、ページングが有効な場合も現在ページの表示範囲だけでなく対象データ全体に対して適用されなければならない。
- **FR-007**: 既存のテーブル列ヘッダーによる並び替え（ニックネーム、タイトル、URL）および既存のインライン編集・フォルダ絞り込み・削除・ピン留め操作の動作を損なわず、ツールバーで並び替え条件を選択した際はテーブル列ヘッダー側のソート状態を解除して競合を防がなければならない。また、データ更新（追加・編集・削除・他タブからの復帰による自動同期）後も適用中の並び替え状態が維持されなければならない。
- **FR-008**: 比較対象の値（最終使用日時またはスコア）が同一である行同士については、再描画のたびに順序が入れ替わらないよう安定した決定的な順序で表示しなければならない。
- **FR-009**: 並び替え機能で新たに追加・変更されるすべての UI ラベル、選択肢名、ツールチップ等は日本語・英語の多言語リソースに定義し、設定された言語に即時追従しなければならない。

### Key Entities *(include if feature involves data)*

- **ブックマーク表示行（Bookmark Row）**: 一覧画面で並び替え対象となる 1 行分のブックマーク情報。ニックネーム、タイトル、URL、ピン留め状態に加え、並び替え基準となる「最終使用日時」および「スコア」を保持する。
- **一覧並び替え設定（List Sort Preference）**: ユーザーが選択したツールバー上の並び替えプリセット（デフォルト順／最終使用日時降順／最終使用日時昇順／スコア降順／スコア昇順）を表す、端末ローカルに永続化される設定値。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは管理画面を開いた状態から、セレクトを開いて項目を選ぶだけの 2 クリック以内で、ブックマーク一覧を「最終使用日時（新しい順／古い順）」および「スコア（高い順／低い順）」へ切り替えられる。
- **SC-002**: 100 件以上のブックマークが登録されている場合でも、並び替え操作およびフォルダ絞り込みとの組み合わせが体感上遅延なく（1 秒以内に）一覧へ反映される。
- **SC-003**: 最終使用日時・スコアの昇順／降順いずれの並び替えでも、同一値を含まないすべての行が厳密に期待される大小順序で表示される（境界値・小数を含むスコア・ピン留め混在時でも逆転やグループ偏りが発生しない）。
- **SC-004**: 並び替え条件を変更して画面を再読み込みまたは再度開いた際、100% 同じ並び替え設定が復元されて表示される。
- **SC-005**: 既存の管理画面操作（列ヘッダーソート、インライン編集、ピン留め切替、フォルダ操作、JSON 編集・エクスポート、削除）が従来通り正常動作し、既存機能の退行が発生しない。

## Assumptions

- 並び替えに使用する「最終使用日時」および「スコア」は、各ブックマークに永続保存されている既存データ値を参照する（閲覧時点での減衰再計算ではなく、オムニボックス／ポップアップでの検索ランキングと整合する保存済みスコア値を用いる）。
- 並び替え選択状態の保存先はデバイス固有のローカル設定領域とし、Google アカウント同期のデータ容量（100KB 上限）や同期データ構造には影響を与えない。
- 既存の検索機能（ポップアップ／オムニボックスのサジェスト順位）のアルゴリズムは変更せず、本機能のスコープはブックマーク管理画面の一覧表示に限定する。
- 最終使用日時やスコアの値が等しい行のタイブレーカーには、既存の表示順またはニックネーム・URL 等の決定的な比較基準を用いる。
