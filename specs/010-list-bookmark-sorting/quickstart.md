# Quickstart & 実機検証ガイド: ブックマーク一覧の並び替え機能

**Feature**: `010-list-bookmark-sorting` | **Date**: 2026-11-17

## 1. 前提・ビルド手順

```bash
npm run build
```

- `package/js/` および `package.zip` がエラーなく生成されることを確認する。
- Chrome で `chrome://extensions/` を開き、「デベロッパーモード」有効化の上で `package/` ディレクトリを読み込む（既に読み込み済みの場合は更新ボタンを押す）。

---

## 2. E2E 検証シナリオ

### シナリオ 1: 初回表示と 5 列固定幅レイアウト維持
1. テスト用の複数ブックマーク（異なる `last_used_at`, `score`, `is_pinned` を持つデータ。11 件以上あるとページングも検証可能）が登録された状態で管理画面（`list.html`）を開く。
2. **期待結果**:
   - テーブル列が従来通り 5 列（ニックネーム、タイトル、URL、ピン留め、操作）のままである。
   - ツールバーにフォルダ絞り込みと並んで「並び替え」セレクトが表示され、初期値は「デフォルト順」になっている。

### シナリオ 2: 最終使用日時による並び替え（P1）
1. ツールバーの「並び替え」セレクトから「最終使用日時（新しい順）」を選択する。
2. 実際にブックマークを 1 件ポップアップまたはオムニボックスから起動して `last_used_at` を更新し、管理画面タブへ戻る（フォーカス復帰）。
3. 次に「最終使用日時（古い順）」を選択する。
4. **期待結果**:
   - 手順 1 で全ページ対象の並び替えが反映され、1 ページ目から表示される。
   - 手順 2 で直前に使用したブックマークが最上位（1 行目）に自動更新される。
   - 手順 3 で最も古く使用されたブックマークが先頭に並ぶ。

### シナリオ 3: スコアによる並び替え・小数比較・ピン留め非優先（P1 / P2）
1. JSON 編集ダイアログ等を使い、`score` が `1.5`, `10.2`, `2.0` などのデータ、および低スコアだが `is_pinned: true` のブックマークを用意する。
2. ツールバーから「スコア（高い順）」および「スコア（低い順）」を選択する。
3. **期待結果**:
   - `10.2 > 2.0 > 1.5` の数値大小で正しく並び、辞書順（`"10.2" < "1.5"`）の逆転が起きない。
   - `is_pinned: true` であってもスコアが低ければ「スコア（高い順）」では下位に、「スコア（低い順）」では上位に表示される（純粋値ソート）。

### シナリオ 4: フォルダ絞り込み・設定永続化・列ヘッダーソートとの切り替え（P2）
1. フォルダ絞り込みで特定フォルダを選択した状態で、「最終使用日時（新しい順）」または「スコア（高い順）」を選ぶ。
2. 管理画面タブを閉じ、再度 `:ls` 等で管理画面を開く。
3. テーブルの「ニックネーム」列ヘッダーをクリックして列ソートを行う。
4. 再度ツールバーの「並び替え」セレクトから「最終使用日時（新しい順）」を選択する。
5. **期待結果**:
   - 手順 1 で絞り込み対象のみがソートされる。
   - 手順 2 でタブを閉じても前回選んだ並び替え条件が復元されて適用されている。
   - 手順 3 で列ヘッダーソートが正常に動作し、ツールバーのセレクト表示は「デフォルト順」へ切り替わる。
   - 手順 4 で列ヘッダーのソートインジケータが解除され、ツールバー選択による並び替えへ戻る。

### シナリオ 5: 多言語表示・レスポンシブ折り返し・既存操作回帰チェック
1. 設定画面（`preferences.html`）で言語を English に切り替え、管理画面を再表示する。
2. ブラウザウィンドウ幅を狭く（例: 600px 程度）し、ツールバーの表示崩れがないか確認する。
3. ソート適用状態でインライン編集・ピン留めトグル・削除を実行する。
4. **期待結果**:
   - ラベル・選択肢が英語表記（`Sort`, `Default`, `Last Used (Newest)` 等）に切り替わる。
   - ツールバーが自然に折り返され、操作ボタンと重ならない。
   - インライン編集やピン留め後も選択中の並び替え状態が維持され、編集中セルへの干渉も起きない。
