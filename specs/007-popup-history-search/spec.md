# Feature Specification: ポップアップ検索でのブラウザ履歴表示（オプトイン権限）

**Feature Branch**: `007-popup-history-search`

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "ポップアップでブックマークを検索する時、候補ブックマークの下にブラウザ履歴から検索された一覧を表示することはできますか。任意権限（案A: 設定画面でオプトイン有効化・初回許可確認）方式で、設計ポイント通りの仕様で仕様書を作成する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 設定画面からの履歴検索機能のオプトイン有効化・無効化 (Priority: P1)

ユーザーは、プライバシーに配慮しつつ、必要な場合のみ設定画面から「ブラウザ履歴検索」を自分の意思で有効化・無効化できるようにしたい。初期状態では履歴アクセス権限を求めず、有効化を操作したタイミングでアクセス許可を求め、許可が得られた場合のみ履歴検索機能が動作するようにしたい。

**Why this priority**: 閲覧履歴は個人情報やプライバシーに関わるデータであるため、最小権限の原則を守り、ユーザーが明示的に望んだ場合にのみ許可を取得して利用可能にすることが本機能の前提条件となるため。

**Independent Test**: 新規インストール直後の状態でポップアップ検索を行っても履歴は表示されず権限も付与されていないこと、また設定画面で履歴検索トグルを ON にするとブラウザのアクセス許可ダイアログが表示され、許可時のみ有効になり、拒否時は無効のまま維持されることを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 拡張機能を導入した初期状態（履歴検索が無効、かつ履歴アクセス許可が未付与の状態）、**When** ユーザーがポップアップで検索を行う、**Then** 登録済みブックマークの候補のみが表示され、ブラウザ履歴からの検索結果および履歴セクションは表示されない。
2. **Given** ユーザーが設定画面を開き「ブラウザ履歴検索」が OFF の状態、**When** トグルを ON に切り替える、**Then** 履歴アクセス許可が未付与であればユーザーにブラウザの許可確認プロンプトが表示され、許可を承認すると設定が ON になり設定保存通知が表示される。
3. **Given** 履歴アクセス許可の確認プロンプトが表示された状態、**When** ユーザーが許可を拒否またはキャンセルする、**Then** 設定は OFF のまま維持され、アクセス許可が得られなかったため有効化できなかった旨のメッセージが設定画面に表示される。
4. **Given** 履歴検索が ON の状態、**When** ユーザーが設定画面でトグルを OFF に切り替える、**Then** 設定が OFF として保存され、直後のポップアップ検索から履歴候補が表示されなくなる。
5. **Given** 設定上は履歴検索が ON になっていたが、その後ブラウザ側の拡張機能詳細設定などで履歴アクセス許可が取り消された状態、**When** 設定画面を開く、またはポップアップで検索を行う、**Then** 権限がない状態を安全に検知してエラーを発生させず、ポップアップではブックマーク検索のみを正常継続し、設定画面では未許可（OFF）相当の状態として再許可を促せるようにする。

### User Story 2 - ポップアップ検索時のブックマーク候補下へのブラウザ履歴候補表示と遷移 (Priority: P1)

履歴検索を有効にしたユーザーは、ポップアップの検索欄にキーワードを入力した際、登録済みブックマークの候補が上部に優先表示されたまま、そのすぐ下に同じキーワードに一致するブラウザ閲覧履歴の一覧を合わせて確認し、キーボードまたはクリックで目的のページを直接開けるようにしたい。

**Why this priority**: ユーザーが求めている中核体験であり、「ブックマークに登録し忘れたページ」や「最近見たページ」を Nickmark のポップアップからシームレスに再訪できるようになる価値の中心であるため。

**Independent Test**: 履歴検索を有効化した状態でポップアップを開き、ブックマークと履歴の双方に一致するキーワードおよび履歴のみに一致するキーワードを入力して、ブックマーク候補の下に重複を除いた履歴一覧が表示されること、および選択して現在のタブ・新規タブ・バックグラウンドタブで開けることを検証できる。

**Acceptance Scenarios**:

1. **Given** 履歴検索が有効で、入力キーワードに一致するブックマーク候補とブラウザ履歴の両方が存在する状態、**When** ポップアップの検索欄に 1 文字以上の通常検索キーワードを入力する、**Then** 上部にブックマーク候補一覧（既存の優先度・スコア順）が表示され、その下部に「履歴」セクション見出しとともに一致するブラウザ履歴候補（サイトアイコン、タイトル、URL、履歴識別バッジ付き）が表示される。
2. **Given** ブックマーク候補には一致する項目が 0 件だが、ブラウザ履歴には一致する項目が存在する状態、**When** ポップアップの検索欄にキーワードを入力する、**Then** 「一致する候補が見つかりませんでした」という空表示にはならず、履歴セクションに該当するブラウザ履歴候補が表示される。
3. **Given** ブックマーク候補とブラウザ履歴の両方に同一の URL が含まれている状態、**When** 検索結果を表示する、**Then** ブックマーク候補側にのみ表示され、同一 URL のエントリは下部の履歴セクションから除外されて二重表示されない。
4. **Given** ポップアップ内で履歴候補が選択（ハイライト）されている状態、**When** `Enter` キー（または通常クリック）を実行する、**Then** 現在のアクティブタブが選択した履歴ページの URL へ遷移し、ポップアップが閉じる。
5. **Given** ポップアップ内で履歴候補が選択されている状態、**When** 修飾キー付きで確定（`Cmd+Enter` / `Ctrl+Enter` / `Alt+Enter`、または `Shift+Enter` / 修飾キー付きクリック）する、**Then** 既存のブックマーク候補と同じ操作体系で新しいフォアグラウンドタブまたはバックグラウンドタブで開き、バックグラウンドタブで開いた場合はポップアップを閉じずに検索欄へフォーカスを維持する。
6. **Given** 履歴候補からページを開いた場合、**When** 遷移が完了する、**Then** 登録済みブックマークの学習スコアや最終使用日時は変更されず、既存のブックマークランキングに悪影響を与えない。

### User Story 3 - キーボード操作・検索モードとの自然な共存 (Priority: P2)

ユーザーは、ブックマーク候補と履歴候補が混在する状態でも、これまで通りキーボードだけで迷わず上下移動・スクロールでき、またコマンド入力中やフォルダ一括オープン操作時には履歴検索結果が割り込んで操作を邪魔しないようにしたい。

**Why this priority**: キーボードファーストのランチャーとしての操作快適性と、コマンド操作（`:add` や `:rm` 等）およびフォルダ操作の正確性を損なわないために重要な体験設計であるため。

**Independent Test**: ブックマーク候補と履歴候補が同時に表示された状態で上下移動・`Tab` キー・スクロールを行うこと、および `:` で始まるコマンド入力や末尾 `/` のフォルダ指定入力時に履歴候補が表示されないことを検証できる。

**Acceptance Scenarios**:

1. **Given** ブックマーク候補の下に履歴候補が表示されている状態、**When** `↓` / `↑` キー（または `Ctrl+N` / `Ctrl+P`）を押し続ける、**Then** ブックマーク候補の末尾から履歴候補の先頭へ（および履歴候補の末尾からブックマーク候補の先頭へ）セクション見出しを飛ばしてシームレスに選択ハイライトが移動し、表示領域外へ移動した場合はリストが自動スクロールする。
2. **Given** 履歴候補を選択（ハイライト）している状態、**When** `Tab` キーを押す、**Then** 履歴候補はニックネームを持たないため検索入力欄の文字は意図せず書き換えられず、現在の検索状態が維持される。
3. **Given** 履歴検索が有効な状態、**When** コマンドモード（`:` で始まる入力）またはフォルダ一括オープン指定（末尾が `/` の入力）を行っている、または確認ダイアログが表示されている、**Then** 履歴検索は実行されず、履歴セクションおよび履歴候補は表示されない。
4. **Given** ユーザーが検索欄に文字列を連続で素早くタイプしたり削除したりしている状態、**When** 非同期の履歴検索が完了する、**Then** 常に最新の入力文字列に対応する検索結果のみが反映され、遅延して返ってきた古い入力の履歴結果でリストが上書きされたりちらついたりしない。

---

### Edge Cases

- **入力が空・空白のみ・スラッシュのみのとき**: ポップアップ起動直後や入力を消去して空にした状態、および空白や `/` のみを入力した状態では、履歴検索は実行せず候補リスト全体を表示しない。
- **ブックマーク・履歴の双方が 0 件のとき**: どちらにも一致する項目がない場合のみ、「一致する候補が見つかりませんでした」等の空状態メッセージを表示する。
- **履歴検索件数が非常に多いとき**: 表示上限（最大 10 件）を設けることで、検索結果が膨大になってポップアップ内の視認性やスクロール操作性が損なわれるのを防ぐ。
- **拡張機能内部ページや検索対象外の特殊 URL**: タイトルや URL が欠損している履歴エントリでもエラーを起こさず表示できること（タイトルが空の場合は URL 等をタイトルとして代替表示する）。
- **アクセス許可の取り消し・失敗**: ユーザーがブラウザ設定から履歴権限を取り消した直後や履歴取得時にエラーが発生した場合でも、ポップアップの検索画面がクラッシュせずブックマーク検索が継続できること。
- **同一 URL の正規化差異（末尾スラッシュ有無など）**: ブックマーク候補としてすでに表示されているページと同じ URL の履歴がある場合は、可能な範囲で重複として判定し履歴側から除外する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは履歴アクセス権限を初期必須権限には含めず、ユーザーが明示的に有効化した際にのみ許可を要求する任意権限（オプトイン）方式を採用しなければならない。
- **FR-002**: システムは設定画面に「ブラウザ履歴検索」の有効／無効を切り替える設定項目、説明文、およびアクセス許可の状態に応じたフィードバック通知を提供しなければならない。
- **FR-003**: ユーザーが設定画面で履歴検索を ON にした際、履歴アクセス権限が未付与であればシステムはアクセス許可を要求し、許可された場合のみ有効設定を保存しなければならない。許可が拒否された場合は設定を OFF のまま維持し、ユーザーへ通知しなければならない。
- **FR-004**: 履歴検索の有効／無効設定は各デバイス固有の設定としてローカルに保存し、デフォルト値は無効（OFF）としなければならない。
- **FR-005**: 履歴検索が有効かつアクセス権限が付与されている状態で、ユーザーがポップアップの検索欄に通常検索クエリ（空白のみ・スラッシュのみ・`:` コマンド・末尾 `/` フォルダ明示指定を除く 1 文字以上の文字列）を入力したとき、システムは既存のブックマーク候補に加えてブラウザ閲覧履歴の検索を実行し、ブックマーク候補の下に履歴候補一覧を表示しなければならない。
- **FR-006**: システムはブックマーク候補セクションと履歴候補セクションが視覚的に明確に区別できるよう、履歴候補の上部にセクション見出し（例：「ブラウザ履歴」/「History」）を表示し、各履歴候補行にサイトアイコン（favicon）、履歴バッジまたは種別表示、ページタイトル、および URL を表示しなければならない。
- **FR-007**: システムは、上部のブックマーク候補にすでに含まれている URL と一致する履歴エントリを履歴候補セクションから重複除外しなければならない。
- **FR-008**: 履歴候補の最大表示件数は 10 件を上限とし、新しい履歴や訪問頻度・関連性の高い履歴が優先して表示されなければならない。
- **FR-009**: ブックマーク候補が 0 件であっても履歴候補が 1 件以上存在する場合は履歴候補一覧を表示し、ブックマーク候補と履歴候補の両方が 0 件の場合のみ一致なしメッセージを表示しなければならない。
- **FR-010**: キーボードでの上下移動（`↑` / `↓`、`Ctrl+N` / `Ctrl+P`）はセクション見出しをスキップしてブックマーク候補と履歴候補の間をシームレスに移動できなければならず、選択変更時はスクロール追従を行わなければならない。
- **FR-011**: 履歴候補の確定操作（クリック、`Enter`、`Cmd/Ctrl/Alt+Enter`、`Shift+Enter`）は通常ブックマークと同じタブ開き方・ポップアップ開閉ルールに従わなければならない。ただし、履歴候補を開いた場合はブックマーク用の学習スコアおよび使用日時を更新してはならない。
- **FR-012**: 履歴候補が選択された状態で `Tab` キーが押された場合、システムは検索入力欄のテキストを書き換えずに維持しなければならない。
- **FR-013**: コマンドモード（`:` 開始）の入力中、確認ダイアログ表示中、および履歴検索無効時は、履歴検索を行わず履歴候補を表示してはならない。
- **FR-014**: 非同期の履歴検索において、後続の入力が先に行われた場合や検索文字列が変更・クリアされた場合、古い検索リクエストの結果を画面に反映してはならない。
- **FR-015**: 設定画面およびポップアップ内で追加・変更されるすべてのラベル、見出し、説明文、および通知メッセージは日本語・英語の双方で定義され、言語設定切り替え時に即座に反映されなければならない。

### Key Entities *(include if feature involves data)*

- **履歴検索設定（Device Preference）**: 各ブラウザ環境ごとに保存される「ブラウザ履歴検索の有効／無効フラグ」。閲覧履歴アクセス権限の許可状態と組み合わせて機能の実効状態を決定する。
- **履歴候補項目（History Suggestion Item）**: ブラウザ閲覧履歴から取得された検索結果の 1 件を表す表示モデル。ページタイトル、URL、最終訪問日時または訪問関連情報、表示用のサイトアイコン情報を含み、ブックマーク候補とは種別上で区別される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 履歴検索を一度も有効にしていないユーザーの 100% に対して、インストール時およびアップデート時に閲覧履歴へのアクセス許可プロンプトが強制表示されない。
- **SC-002**: 設定画面から履歴検索を有効化・許可したユーザーは、即座に（ページ再起動や再インストール不要で）次のポップアップ検索から履歴候補を利用開始できる。
- **SC-003**: 通常検索時のポップアップにおいて、履歴検索を有効化した状態でもブックマーク候補の表示は入力直後に遅延なく描画され、履歴候補も通常の操作感覚を損なわない応答速度（おおむね 300ms 以内）でブックマーク候補の下に追加表示される。
- **SC-004**: ブックマーク候補と重複する URL の二重表示率が 0% であり、かつ履歴候補を選択して開いた際に既存ブックマークの優先順位・学習スコアへの意図しない変更が 0 件である。
- **SC-005**: キーボードのみ（マウス不使用）で、ポップアップ起動 → 検索語入力 → ブックマーク候補から履歴候補へのハイライト移動 → `Enter` / 修飾キー付き `Enter` によるページ遷移までの操作フローが完結できる。

## Assumptions

- **履歴検索の最大件数**: ポップアップの高さを圧迫しすぎず、かつ十分な候補を提示できる実用的な上限として、履歴候補の表示上限は **10 件** とする。
- **履歴の検索対象期間**: ブラウザのデフォルト履歴検索範囲（直近数十日〜全期間相当のブラウザ履歴）を対象とし、キーワード（スペース区切りの場合もブラウザ履歴検索のテキスト一致に従う）でタイトル・URL を横断検索する。
- **タイトル欠損時のフォールバック**: 履歴エントリのタイトルが空文字の場合は、URL を主タイトルとして表示する。
- **重複判定の範囲**: ブックマーク候補リストにすでに表示されている URL と同一（または末尾スラッシュ等の正規化後に同一）とみなせる履歴エントリを除外対象とする。なお、動的 URL（`%s` を含むブックマーク）が展開された後の URL と履歴 URL が一致する場合も重複とみなして除外する。
- **`Tab` キーの挙動**: 履歴候補にはニックネームが存在しないため、誤って入力欄の検索語が長い URL で上書きされるのを防ぐ目的で、履歴候補ハイライト中の `Tab` キー押下時は入力欄を書き換えない設計とする。
- **オムニボックス（アドレスバー）は対象外**: 本機能は新しいコマンドパレット型ポップアップ検索を対象とし、将来廃止予定であるアドレスバー（`nm` オムニボックス）への履歴候補追加は行わない。
- **設定の同期対象外**: 閲覧履歴への許可状態はブラウザ／デバイス単位で管理されるため、履歴検索の有効／無効設定は Google アカウント同期の対象外（ローカルデバイス固有設定）とする。
