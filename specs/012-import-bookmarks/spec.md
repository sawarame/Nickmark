# Feature Specification: ブックマークのインポート機能

**Feature Branch**: `013-import-bookmarks`

**Created**: 2026-11-17

**Status**: Draft

**Related Issue**: #23 (`https://github.com/sawarame/Nickmark/issues/23`)

**Input**: User description: "GitHub Issue #23: エクスポート機能はあるが、インポート機能がないのでつける"

**Clarifications Applied**:
- **適用方式（マージ / 上書き）**: インポート確認ダイアログ上でユーザーが「マージ（既存データへ追加・統合）」と「上書き（既存データをすべて置換）」を選択できるようにする。
- **対応ファイル形式**: Nickmark エクスポート JSON 形式（`{ "bookmarks": { ... } }`）と、Chrome 標準のブックマーク HTML 形式（Netscape Bookmark File Format）の両方を対象とする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Nickmark エクスポート JSON ファイルからのインポート（マージ・上書き選択） (Priority: P1)

ユーザーは別端末でエクスポートしたバックアップファイルや手元の JSON ファイルを管理画面から読み込み、確認ダイアログ上で「既存データへのマージ（統合）」または「既存データの上書き（完全復元）」を選択してブックマークを取り込みたい。

**Why this priority**: 既存のエクスポート機能と直接対になる中核機能であり、バックアップからの復元や端末間のデータ移行において最優先で必要とされるため。

**Independent Test**: 管理画面の「インポート」操作から Nickmark 形式の JSON ファイルを選択し、プレビュー確認ダイアログで取り込み件数を確認した上で「マージ」および「上書き」のそれぞれを実行し、一覧テーブルの内容とストレージ保存状態が選択した方式通りに更新されることを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 管理画面を開いている状態、**When** ユーザーが管理画面のインポートボタンから有効な Nickmark エクスポート JSON ファイルを選択する、**Then** 選択したファイル名・検出形式・取り込み対象件数（ニックネーム数およびブックマーク総数）を表示し、「マージ」と「上書き」を選べる確認ダイアログが開く。
2. **Given** 既存のブックマークが登録されており、確認ダイアログで別データを含む JSON ファイルが読み込まれている状態、**When** ユーザーが「マージ」を選択してインポートを実行する、**Then** 既存データは消去されず、新規ニックネーム・新規 URL が追加され、同一ニックネームかつ同一 URL の重複エントリは既存情報と安全に統合された上で一覧に即座に反映される。
3. **Given** 既存のブックマークが登録されており、確認ダイアログでバックアップ JSON ファイルが読み込まれている状態、**When** ユーザーが「上書き」を選択してインポートを実行する、**Then** 既存のブックマークデータはすべてインポートファイルの内容で置き換えられ、一覧に即座に反映される。
4. **Given** 確認ダイアログが開かれている状態、**When** ユーザーが「キャンセル」を選択する、**Then** 既存データは一切変更されずにダイアログが閉じる。

### User Story 2 - Chrome 標準ブックマーク HTML ファイルからのインポート (Priority: P1)

ユーザーは Chrome ブラウザの標準機能でエクスポートしたブックマーク HTML ファイルを読み込み、フォルダ階層とブックマークタイトルを活かしたニックネーム形式で Nickmark に一括登録したい。

**Why this priority**: Issue #23 のスコープとしてユーザーが明示的に要求した主要ユースケースであり、新規ユーザーが既存のブラウザブックマーク資産を Nickmark へ移行するための直接的な導線となるため。

**Independent Test**: Chrome からエクスポートした複数階層のフォルダとブックマーク（通常 URL・ブックマークレット・空タイトル等を含む）が記述された HTML ファイルをインポートし、階層構造が `/` 区切りのフォルダおよびニックネームに変換されて取り込まれることを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** フォルダ階層とブックマーク項目を含む Chrome 標準ブックマーク HTML ファイル、**When** ユーザーが管理画面のインポートボタンからその HTML ファイルを選択する、**Then** ファイルが Chrome ブックマーク HTML 形式として自動判別され、抽出された対象件数および任意の取り込み先ベースフォルダを指定できるプレビュー確認ダイアログが表示される。
2. **Given** HTML 内に `Dev > GitHub` のようなフォルダ階層とタイトルを持つブックマークが含まれている状態、**When** ユーザーがインポートを実行する、**Then** フォルダパスとサニタイズ済みタイトルを組み合わせたニックネーム（例: `Dev/GitHub`）が生成され、元のタイトル文字列を保持した状態で一覧およびフォルダフィルタに反映される。
3. **Given** 同じファイル選択で既存のブックマークが残っている状態、**When** ユーザーがインポート先ベースフォルダ（例: `chrome`）を任意入力して「マージ」または「上書き」を実行する、**Then** 変換後のすべてのニックネームの先頭に指定したベースフォルダプレフィックスが付与されて取り込まれる。

### User Story 3 - 不正データの検証・同期容量ガードおよび多言語・操作保護 (Priority: P2)

ユーザーは破損したファイルや仕様外のファイルを誤って取り込んでも既存データが破壊されず、Google アカウント同期の容量制限を超える場合も事前・保存時に明確なエラー案内を受け取りたい。また、表示言語設定に応じたわかりやすい日本語／英語の画面表記・通知を得たい。

**Why this priority**: インポート処理は大量データを一括で書き換える操作であるため、誤った構造や容量超過による既存データ消失を防ぐ安全性と、多言語環境での一貫したフィードバックが不可欠なため。

**Independent Test**: 不正な JSON、空ファイル、対応外の HTML ファイル、必須 URL が欠落したデータ、あるいは同期有効状態で 100KB を超過するデータをインポートしようとした際に、既存データが一切変更されずエラーメッセージが表示されること、および日本語／英語切り替え時に UI 文言が追従することを検証できる。

**Acceptance Scenarios**:

1. **Given** 構文エラーのある JSON ファイル、ニックネームが空または配列でない不正構造の JSON、またはブックマーク項目が 1 件も含まれない HTML ファイル、**When** ユーザーがインポート対象として選択する、**Then** データは保存されず、原因がわかる多言語対応のエラー通知が表示される。
2. **Given** Google アカウント同期が有効になっており、インポート結果の総データサイズが同期上限（100KB）を超える状態、**When** ユーザーがインポートを実行する、**Then** 保存処理が安全に中断され、既存データは保護されたまま同期容量超過を示すエラー通知が表示される。
3. **Given** 同じファイル内容を続けて再選択する操作、**When** ユーザーが一度キャンセルまたはエラーになった後に同じファイルを再選択する、**Then** 連続して同じファイルを選択しても正常にファイル選択イベントが検知され、確認ダイアログや処理が再度起動する。

### Edge Cases

- **欠損フィールドを含む手書き・部分 JSON**: `url` が有効で空文字でなければ、`title`（省略時は空文字）、`score`（省略時は `1.0`）、`created_at` / `last_used_at`（省略時は現在時刻）、`is_pinned`（省略時は `false`）が安全なデフォルト値で補完されること。
- **JSON ルートキーの揺れ**: 標準のエクスポート形式（`{ "bookmarks": { ... } }`）だけでなく、テストや手編集で `{ "bookmarks": ... }` の外側キーがなく直接ニックネーム辞書を記述した JSON（各値がブックマーク配列）が渡された場合も、安全に構造検証した上で受け入れること。ただし配列そのものやプリミティブ値、必須項目欠落は明確に拒否すること。
- **ニックネーム・フォルダパスの正規化**: JSON・HTML どちらからのインポートでも、先頭・末尾・連続スラッシュ（`/work//gh/` 等）は正規化され、スラッシュのみの空キーは無効として除外・エラー検知されること。
- **HTML 内の特殊スキームと文字**: `http://`, `https://`, `file://`, `javascript:`（ブックマークレット）は有効な遷移・実行対象として取り込まれ、`place:` や `about:` 等のブラウザ内部専用スキームや空の `HREF` は安全にスキップされること。また HTML エンティティ（`&amp;`, `&quot;` 等）を含むタイトルや URL が正しくデコードされること。
- **HTML タイトル内の空白やスラッシュ**: HTML ブックマークのタイトルやフォルダ名に `/` や空白が含まれる場合、フォルダ階層の誤分割やコマンド入力時の引数区切り衝突を防ぐため `-` へサニタイズしてニックネームが生成されること（元のタイトル文字列自体は `title` フィールドにそのまま保持）。
- **HTML の空タイトルおよび `ADD_DATE`**: リンクタイトルが空の場合は URL のホスト名（取得不可時は `bookmark`）からニックネームを生成し、`ADD_DATE` 属性が有効な Unix 秒またはミリ秒であれば作成日時・最終使用日時へ変換して引き継ぐこと。
- **同一ニックネーム・同一 URL の重複**: マージ時および同一ファイル内に同じニックネームと同一 URL（末尾エンコード差異等を含む）が存在する場合は重複登録されず、既存のスコア・最新使用日時・最古作成日時・ピン留め・非空のタイトル／デフォルト値を優先して 1 件に統合されること。
- **インライン編集や他ダイアログとの競合回避**: インポート確認ダイアログが開かれている間は、他タブからのフォーカス復帰による自動再読込が作業中の状態を上書きしないこと。またインポート確定前にインライン編集中のセルがあっても不整合が起きないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理画面のブックマーク管理セクション（既存のエクスポートボタン周辺）に「インポート」操作ボタンを配置し、ユーザーがローカルのファイル（`.json`, `.html`, `.htm`）を選択してインポートフローを開始できなければならない。
- **FR-002**: システムは選択されたファイルの内容を解析し、Nickmark エクスポート JSON 形式および Chrome 標準ブックマーク HTML 形式（Netscape Bookmark File Format）を自動判別して読み込めなければならない。
- **FR-003**: インポートファイルの解析が成功した際、直ちにストレージを上書きするのではなく、ファイル名・検出されたファイル形式・抽出されたブックマーク件数（およびニックネーム数）を提示する確認ダイアログを表示し、ユーザーが適用方式として **「マージ（既存データと統合）」** または **「上書き（既存データを置換）」** を明示的に選択できなければならない。
- **FR-004**: Chrome ブックマーク HTML 形式をインポートする際は、`<H3>` によるフォルダ階層を `/` 区切りで維持しつつ、フォルダ名およびリンクタイトルから Nickmark で検索・コマンド実行しやすいサニタイズ済みニックネーム（`/` や空白を `-` に置換）を自動生成しなければならない。また確認ダイアログ上で任意の取り込み先ベースフォルダプレフィックスを指定できるオプションを提供しなければならない。
- **FR-005**: Chrome ブックマーク HTML 形式の解析において、遷移・実行可能な URL（`http://`, `https://`, `file://`, `javascript:`）を取り込み対象とし、ブラウザ内部スキームや空 URL はスキップしてスキップ件数を必要に応じて把握・安全処理できなければならない。また `ADD_DATE` 属性がある場合は作成・最終使用日時として引き継がなければならない。
- **FR-006**: Nickmark JSON 形式の解析において、必須項目（非空の文字列 `url` および妥当なニックネーム配列構造）を検証し、省略可能なメタデータ（`title`, `score`, `last_used_at`, `created_at` 等）が欠損している場合は安全なデフォルト値で補完しなければならない。
- **FR-007**: マージモード実行時は既存のブックマークデータを保持したままインポートデータを統合し、同一ニックネームかつ同一 URL が重複する場合は重複行を増やさず、スコア・日時・ピン留め状態・非空メタデータを統合して 1 件にまとめなければならない。上書きモード実行時は既存データをインポートデータ全体で置き換えなければならない。
- **FR-008**: インポートの保存前にデータ構造の正規化および Google アカウント同期有効時の容量上限（100KB）チェックを行い、不正ファイルまたは容量超過が発生した場合は既存データを一切変更せずエラー通知を表示して中断しなければならない。
- **FR-009**: インポート完了後、管理画面のブックマーク一覧・フォルダフィルタ・ページング表示を即座に最新状態へ更新し、適用結果（取り込み件数など）を含む完了トースト通知を表示しなければならない。
- **FR-010**: インポート機能で追加するすべてのボタンラベル、ダイアログ見出し・説明文、フォームラベル、および成功・警告・エラー通知メッセージは日本語・英語の多言語リソースに定義し、選択中の言語設定に追従させなければならない。

### Key Entities *(include if feature involves data)*

- **インポートファイル（Import Source File）**: ユーザーが管理画面から選択するバックアップまたは移行元ファイル。Nickmark エクスポート JSON 形式、または Chrome 標準ブックマーク HTML 形式のいずれかの構造を持つ。
- **インポート解析結果（Parsed Import Result）**: ファイルを解析・正規化・サニタイズした結果として得られるブックマーク候補辞書、検出形式（JSON / HTML）、有効ブックマーク総数、および HTML 解析時のスキップ件数などのサマリー情報。
- **インポート適用モード（Import Apply Mode）**: 確認ダイアログ上でユーザーが選択するデータ反映方針。「マージ（既存データに統合）」または「上書き（既存データを完全置換）」の 2 種類を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは管理画面を開いた状態から、ファイル選択および確認ダイアログでのモード選択（マージまたは上書き）の最小ステップ（3 アクション以内）で JSON または HTML ファイルのインポートを完了できる。
- **SC-002**: 100 件以上のブックマークを含む JSON または Chrome ブックマーク HTML ファイルをインポートした場合でも、解析・プレビュー表示・保存・一覧再描画が 1 秒以内に完了する。
- **SC-003**: 既存の JSON エクスポートで出力したファイルをそのまま上書きまたはマージインポートした際、ニックネーム・タイトル・URL・ピン留め・デフォルト値・スコア・使用日時が欠損なく忠実に復元される（ラウンドトリップ整合性 100%）。
- **SC-004**: 不正形式ファイルまたは同期容量（100KB）超過ファイルのインポートを試行した場合、既存ブックマークデータの破壊・消失発生率が 0% である。

## Assumptions

- インポートの操作入口は管理画面（ブックマーク一覧画面）に集約し、ポップアップランチャーやオムニボックスコマンドからのファイルアップロードは今回の対象外とする（ブラウザのファイル選択ダイアログがポップアップ閉じを引き起こす制約を避けるため）。
- Chrome 以外のブラウザ（Edge, Firefox, Safari 等）がエクスポートする標準 Netscape Bookmark HTML 形式も同一の HTML 構造であるため、基本的な互換動作が期待できる。
- Chrome ブックマーク HTML 内の最上位フォルダ（例:「ブックマーク バー」「その他のブックマーク」）は、構造保持とフォルダ衝突回避のためデフォルトでは階層に含めて取り込み、必要に応じてユーザーが管理画面のフォルダ名変更機能やインポート時のベースフォルダ指定で整理できるものとする。
