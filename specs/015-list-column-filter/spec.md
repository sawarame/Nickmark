# Feature Specification: ブックマーク一覧の列別フィルター機能

**Feature Branch**: `016-list-column-filter`

**Created**: 2026-11-18

**Status**: Draft

**Related Issue**: #29 (https://github.com/sawarame/Nickmark/issues/29)

**Input**: User description: "ブックマーク一覧の「ニックネーム」「タイトル」「URL」の項目にフィルターボタンをつけて、フィルターボタンをクリックするとテキストエリアが表示され、検索ワードが入力でき、入力したワードで一覧を絞り込むことができる。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 列ヘッダーのフィルターボタンによる検索欄の表示と単一列絞り込み (Priority: P1)

ユーザーは、ブックマーク一覧画面（`list.html`）のテーブルにある「ニックネーム」「タイトル」「URL」の各列ヘッダーに配置されたフィルターボタンをクリックすることで、その列の検索ワード入力欄（テキストエリア）を表示し、入力したキーワードを含むブックマークだけをリアルタイムに絞り込んで探せるようにしたい。

**Why this priority**: Issue #29 の中核要件であり、登録件数が増えたブックマーク一覧の中から特定のニックネーム・タイトル・URL を持つエントリを素早く見つけ出すための基本機能であるため。

**Independent Test**: ブックマーク一覧画面で「ニックネーム」「タイトル」「URL」のいずれかの列ヘッダーにあるフィルターボタンをクリックし、表示されたテキストエリアに検索ワードを入力すると、該当列にそのワードを含む行のみに一覧が絞り込まれ、再度ボタンをクリック（またはクリア操作）すると絞り込みが解除されることを単独で検証できる。

**Independent Test Scenarios / Acceptance Scenarios**:

1. **Given** ブックマーク一覧画面が表示されている状態、**When** 「ニックネーム」「タイトル」「URL」のいずれかの列ヘッダーにあるフィルターボタンをクリックする、**Then** 列のソートを発火させることなく該当列ヘッダー内に検索ワード入力用のテキストエリアが表示され、自動的にフォーカスが当たる。
2. **Given** いずれかの列のフィルター入力欄が表示されている状態、**When** 検索ワードを入力する、**Then** 大文字・小文字を区別せず、該当列の値に入力ワードが含まれるブックマーク行のみに一覧（全ページ対象）がリアルタイムに絞り込まれ、ページネーションが先頭ページ（1 ページ目）にリセットされる。
3. **Given** フィルター入力欄が表示されている状態、**When** クリアボタンを押すか入力欄のテキストを消去してフィルターボタンを再クリックする、**Then** 該当列の絞り込みが解除されて全件表示に戻り、入力欄が非表示になる。

---

### User Story 2 - 複数列フィルターおよび既存フォルダ絞り込み・並び替えとの連携 (Priority: P1)

ユーザーは、「ニックネーム」「タイトル」「URL」の複数の列で同時にフィルター条件を指定したり、上部ツールバーの「フォルダ」絞り込みや「並び替え」と組み合わせて目的のブックマークを精密に絞り込み・整列できるようにしたい。また、どの列でフィルターが有効になっているかを視覚的に判別できるようにしたい。

**Why this priority**: 実際の管理作業では「特定フォルダ内の特定ドメインの URL」や「特定のニックネーム接頭辞かつ特定タイトルの項目」を絞り込んでインライン編集や削除を行うケースが多いため。

**Independent Test**: 複数の列（例: ニックネーム列と URL 列）のフィルターを開いてそれぞれ検索ワードを入力し、さらにフォルダ選択やソート順を切り替えた際、すべての条件を満たす行（AND 条件）のみが正しく並び替えられて表示されることを検証できる。

**Acceptance Scenarios**:

1. **Given** 「ニックネーム」列のフィルターに `work`、「URL」列のフィルターに `github` が入力されている状態、**When** 一覧テーブルを確認する、**Then** ニックネームに `work` を含み、かつ URL に `github` を含むブックマークのみ（AND 条件）が表示される。
2. **Given** 上部ツールバーで特定のフォルダが選択されており、かつ列フィルターに検索ワードが入力されている状態、**When** 一覧テーブルおよび並び替えを確認する、**Then** 選択フォルダ配下かつ列フィルター条件を満たす行のみが、指定された並び替え順（ツールバーソートまたは列ヘッダーソート）で表示される。
3. **Given** いずれかの列に検索ワードが入力されて絞り込みが適用されている状態、**When** 列ヘッダーを見る、**Then** 該当列のフィルターボタンがアクティブ状態として強調表示され、現在どの列で絞り込みが行われているか一目で判別できる。

---

### User Story 3 - インライン編集・固定列幅レイアウト・多言語対応との調和 (Priority: P2)

ユーザーは、列フィルターを使用している最中もテーブルの固定列幅レイアウトが崩れず、絞り込んだ結果の行に対してそのままインライン編集・ピン留め・削除を行えるようにしたい。また、日本語・英語の言語設定に応じてフィルターボタンのツールチップやプレースホルダーが適切に表示されるようにしたい。

**Why this priority**: 既存のインライン編集機能や固定 5 列レイアウト、多言語即時切り替えといった Nickmark の品質基準（Constitution）を維持するため。

**Independent Test**: フィルター展開・入力時にテーブルの列幅が変動しないこと、絞り込み結果のセルをクリックしてインライン編集・保存できること、および日英言語設定に応じたラベルが表示されることを検証できる。

**Acceptance Scenarios**:

1. **Given** 列フィルターで一覧が絞り込まれている状態、**When** 表示されている行のニックネーム・タイトル・URL セルをクリックしてインライン編集し保存する、**Then** 編集内容が正常に保存され、フィルター条件も維持されたまま最新の一覧が反映される。
2. **Given** 言語設定が「日本語」または「英語」の状態、**When** フィルターボタンにマウスホバーする、またはフィルター入力欄を表示する、**Then** 選択中の言語に応じたツールチップおよびプレースホルダーが表示される。

---

### Edge Cases

- **列ヘッダークリックによるソートとの分離**: フィルターボタンや展開されたテキストエリアをクリック・キー入力（`Enter`, `Space`, 矢印キー等）した際に、親要素である列ヘッダーのソート（`sortable`）が誤って発火しないこと。
- **改行入力や前後空白の扱い**: テキストエリア内で `Enter` キーを押した際に不要な改行が入力されて検索が外れるのを防ぐ（1 行入力として扱い、`Escape` キーで入力クリアまたはフィルター欄を閉じられるようにする）。また、前後の空白はトリムし、スペース区切りで複数ワードが入力された場合はすべてのワードを含む行（AND 部分一致）として絞り込む。
- **該当件数が 0 件の場合**: フィルター条件に一致するブックマークが 1 件もない場合でも、列ヘッダー内のフィルター入力欄は消えずに維持され、ユーザーがそのまま検索ワードを修正・クリアできること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ブックマーク一覧画面（`src/List.vue`）の `DataTable` における「ニックネーム (`nickname`)」「タイトル (`title`)」「URL (`url`)」の 3 列すべてのヘッダーに、フィルター入力欄の表示／非表示を切り替えるフィルターボタンを配置しなければならない。
- **FR-002**: ユーザーが列ヘッダーのフィルターボタンをクリックした際、該当列のヘッダー内に検索ワード入力用のテキストエリア（`Textarea`）を表示し、自動的にフォーカスを当てなければならない。
- **FR-003**: フィルター入力欄に検索ワードが入力された場合、該当列の値に対して大文字・小文字を区別しない部分一致（スペース区切りの複数キーワード入力時は各キーワードの AND 部分一致）で一覧データをリアルタイムに絞り込まなければならない。
- **FR-004**: 複数の列にフィルターワードが入力されている場合、および上部ツールバーのフォルダ絞り込みが選択されている場合は、すべての条件を同時に満たす行（AND 条件）を表示しなければならない。
- **FR-005**: フィルター条件が変更された際は、現在表示中のページ番号が範囲外になるのを防ぐため、テーブルのページネーションを 1 ページ目（先頭）へリセットしなければならない。
- **FR-006**: フィルターボタンおよびテキストエリアへのクリック・キー操作時はイベント伝播を制御し、列ヘッダーのソート機能（`sortable`）が誤動作しないようにしなければならない。
- **FR-007**: 各列のフィルター入力欄には入力値を即座に消去できるクリア手段（クリアボタン、またはボタン再クリックによる解除）を提供し、フィルター適用中の列はフィルターボタンを視覚的に強調表示しなければならない。
- **FR-008**: フィルター入力欄の展開・入力時も既存の固定列幅レイアウト（`table-layout: fixed`）を維持し、レイアウト崩れを発生させてはならない。
- **FR-009**: フィルター機能に関するすべての UI 文言（ボタンのツールチップ、入力欄のプレースホルダー、クリアボタンのラベル等）は `package/_locales/{ja,en}/messages.json` に定義し、日本語・英語の双方に対応しなければならない。

### Key Entities *(include if feature involves data)*

- **列フィルター状態（Column Filter State）**: `nickname`、`title`、`url` の各列に対する表示開閉フラグ（`open: boolean`）および検索クエリ文字列（`query: string`）を保持する画面状態モデル。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「ニックネーム」「タイトル」「URL」の 3 列すべてにおいて、フィルターボタンのクリックから 100ms 以内にテキストエリアが表示されてフォーカスが当たり、そのままタイピングを開始できる。
- **SC-002**: フィルター入力欄への文字入力時、100% のケースで列ソート誤発火 0 回かつリアルタイムに絞り込み結果が更新される。
- **SC-003**: 単一列絞り込み・複数列 AND 絞り込み・フォルダ絞り込み併用・ソート併用のすべての組み合わせにおいて、条件に合致するブックマーク行が 100% 正確に抽出される。
- **SC-004**: 日本語・英語の言語設定切り替え時、フィルター関連のツールチップおよびプレースホルダーが 100% 選択言語で表示される。

## Assumptions

- 列フィルターの入力状態は一覧画面上で一時的に絞り込み検索を行うための UI 状態であり、ページ再読み込み時には初期状態（フィルター未適用・入力欄非表示）にリセットされる。
- テキストエリア（`Textarea`）は列ヘッダー内の高さを圧迫しないよう 1 行（`rows="1" autoResize`）でコンパクトに表示し、`Enter` キー押下時は改行を挿入しない仕様とする。
