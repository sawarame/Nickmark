# Feature Specification: 定番ブックマーク・ブックマークレットのプリセット機能

**Feature Branch**: `015-preset-bookmarks`

**Created**: 2026-11-18

**Status**: Draft

**Related Issue**: #28 (https://github.com/sawarame/Nickmark/issues/28)

**Input**: User description: "ブックマークやブックマークレットに定番のものをプリセットとして準備し、チェックボックスで使用可否を選択できるようにする（通常のJSONブックマーク形式で保存すると容量が無駄になるため、チェックボックスの有無だけ保存する）。初期状態はすべてOFF、Tipsにプリセットの案内を追加、有効化IDリストはGoogleアカウント同期対象とする。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 設定画面でのプリセット有効化と検索・遷移・実行 (Priority: P1)

ユーザーは、Google 検索（`g`）や GitHub 検索（`gh`）、Markdown リンクコピー（`mdlink`）などの定番の動的 URL・ブックマークレットをいちいち手動で `:add` 登録しなくても、設定画面のチェックボックスを ON にするだけで即座にポップアップやアドレスバー（オムニボックス）から「`g 検索ワード`」や「`mdlink`」として呼び出せるようにしたい。また、プリセットは通常のブックマークデータ（JSON）として保存せず、有効化されたプリセット ID のみを保存することでストレージ容量を無駄に消費しないようにしたい。

**Why this priority**: Issue #28 の中核要件であり、定番の検索 URL やブックマークレットを手間なく容量ゼロに近い形で即戦力として使えるようにすることが本機能の最大の価値であるため。

**Independent Test**: 初期状態で全プリセットが OFF であることを確認した上で、設定画面から任意のプリセット（例: `g` と `mdlink`）にチェックを入れ、ポップアップおよびオムニボックスで `g typescript` を入力して Google 検索へ遷移できること、`mdlink` を実行して現在のページの Markdown リンクがクリップボードにコピーされること、さらにブックマーク一覧画面（`list.html`）やエクスポート JSON にはプリセットが含まれないことを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 拡張機能を新規導入またはプリセット未設定の状態、**When** 設定画面を開く、**Then** 標準収録された全 12 件のプリセット（動的 URL 10 件、ブックマークレット 2 件）がチェックボックス一覧として表示され、初期状態はすべて OFF（未チェック）になっている。
2. **Given** 設定画面で `g`（Google 検索）のチェックボックスを ON にした状態、**When** ポップアップまたはオムニボックスで `g Chrome Extension` と入力して確定する、**Then** `https://www.google.com/search?q=Chrome%20Extension` へ遷移し、引数なしで `g` のみ入力して確定した場合はオリジン（`https://www.google.com`）へ遷移する。
3. **Given** 設定画面で `mdlink`（Markdown リンクをコピー）または `wayback`（Wayback Machine で表示）のチェックボックスを ON にした状態、**When** 一般の Web ページ上でポップアップまたはオムニボックスから該当プリセットを実行する、**Then** `mdlink` は現在のページの `[タイトル](URL)` をクリップボードへコピーし、`wayback` は現在のページ URL を Wayback Machine（`https://web.archive.org/web/*/<現在URL>`）で開く。
4. **Given** 複数のプリセットを ON にし、何回か検索・遷移を実行した状態、**When** ブックマーク一覧画面のテーブルや JSON エディタ・JSON エクスポートを確認する、**Then** 通常のブックマークデータにはプリセットが一切書き込まれておらず、有効化されたプリセット ID リストのみが軽量に保存されている。

### User Story 2 - ユーザー登録ブックマークとの優先度制御と Google アカウント同期連携 (Priority: P1)

ユーザーは、自分が手動で登録・学習させたブックマークがプリセットによって邪魔されないようにしたい。また、Google アカウント同期を有効にしている場合は、どのプリセットを有効化したかというチェック状態もデバイス間で同期されるようにしたい。

**Why this priority**: 既存のブックマーク資産との競合を防ぎつつ、マルチデバイス環境でも同じプリセット環境を維持できるようにすることは実用上不可欠な要件であるため。

**Independent Test**: プリセットと同じニックネーム（例: `g`）に別 URL のユーザーブックマークを登録して使用（スコア上昇またはピン留め）した際に常にユーザー登録側が上位に表示されること、同一ニックネームかつ同一 URL を手動登録した場合は重複表示されないこと、および同期 ON 時に有効化プリセット ID リストが同期ストレージへ保存・移行されることを検証できる。

**Acceptance Scenarios**:

1. **Given** プリセット `g` が ON であり、かつユーザーが手動でニックネーム `g` に別の URL を登録して複数回使用（スコア `> 1.0`）またはピン留めしている状態、**When** `g` で検索する、**Then** プリセットは常に固定スコア（`score: 1.0`、ピン留めなし）として扱われるため、ユーザー登録側のブックマークが常にプリセットより上位に表示される。
2. **Given** プリセット `g`（`https://www.google.com/search?q=%s`）が ON であり、かつユーザーが手動でも同じニックネーム `g` に同じ URL `https://www.google.com/search?q=%s` を登録している状態、**When** `g` で検索する、**Then** 検索候補が二重に表示されることなく、ユーザー登録側のエントリのみが表示される。
3. **Given** Google アカウント同期が ON の状態、**When** 設定画面でプリセットのチェックボックスを切り替える（または同期を ON/OFF 移行する）、**Then** 有効化されたプリセット ID リストが同期対象として保存・反映される。

### User Story 3 - ポップアップ Tips によるプリセット機能の発見と多言語対応 (Priority: P2)

ユーザーは、すべてのプリセットが初期状態で OFF であっても、ポップアップ起動時の空白領域に表示される Tips を通じて「設定画面から便利なプリセットを有効化できる」ことに気づけるようにしたい。また、日本語・英語の言語設定に応じてプリセットのタイトル・説明・Wikipedia の検索先ドメインや Tips 文言が適切に切り替わるようにしたい。

**Why this priority**: 初期状態がすべて OFF であるため、ユーザーがプリセット機能の存在に気づける導線（Discoverability）と、既存の多言語体験との一貫性を確保するため。

**Independent Test**: ポップアップの Tips を切り替えてプリセット案内 Tip が日本語・英語で表示されること、設定画面で言語を切り替えるとプリセット一覧のタイトル・説明が即座に切り替わること、および英語設定時に `wiki` プリセットが英語版 Wikipedia（`en.wikipedia.org`）を検索先とすることを検証できる。

**Acceptance Scenarios**:

1. **Given** ポップアップを起動して検索欄が空の状態、**When** Tips が表示される（またはクリックで Tips を切り替える）、**Then** カタログ内に「設定画面（`:prefs`）から定番の検索・ブックマークレットのプリセットを有効化できる」旨のヒントが含まれており、日本語・英語双方で自然に表示される。
2. **Given** プリセット `wiki` が ON の状態、**When** 表示言語が「日本語」のときと「英語」のときでそれぞれ `wiki test` を検索する、**Then** 日本語設定時は `https://ja.wikipedia.org/w/index.php?search=test`、英語設定時は `https://en.wikipedia.org/w/index.php?search=test` が候補・遷移先として解決される。

### Edge Cases

- **プリセットに対する `:rm` やフォルダ操作**: プリセットは通常のブックマークストレージには存在しないため、`:rm` コマンドの削除候補や対象には含めず、設定画面のチェックボックスから ON/OFF を管理する。
- **ブックマーク保存時の同期ストレージ消去との共存**: Google アカウント同期が ON の状態で通常ブックマークを保存（チャンク再書き込み）した際、同期ストレージ上の有効化プリセット ID リストが誤って消去されないこと。
- **未知・廃止されたプリセット ID がストレージに含まれていた場合**: 将来のバージョン等で定義に存在しない ID がストレージに残っていた場合でも、エラーを起こさず有効な定義済みプリセット ID のみを安全にフィルタリングして扱うこと。
- **`mdlink` ブックマークレット実行時の特殊文字エスケープと通知**: ページタイトルに `[` や `]` が含まれる場合でも適切に処理し、クリップボードへのコピー成功時に視覚的フィードバック（または安全なフォールバック）が行われること。また、`chrome://` 等のスクリプト実行禁止ページや「ユーザー スクリプトを許可する」未有効時は既存のブックマークレット実行機構に従い適切にエラー案内されること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、以下の全 12 件の標準プリセット（動的 URL 10 件、ブックマークレット 2 件）を内蔵カタログとして提供しなければならない。
  - 動的 URL（10 件）:
    - `g`: Google 検索 / Google Search (`https://www.google.com/search?q=%s`)
    - `yt`: YouTube 検索 / YouTube Search (`https://www.youtube.com/results?search_query=%s`)
    - `gh`: GitHub 検索 / GitHub Search (`https://github.com/search?q=%s`)
    - `map`: Google マップ検索 / Google Maps (`https://www.google.com/maps/search/%s`)
    - `tr`: Google 翻訳 / Google Translate (`https://translate.google.com/?text=%s`)
    - `wiki`: Wikipedia 検索 / Wikipedia（日本語設定時: `https://ja.wikipedia.org/w/index.php?search=%s`、英語設定時: `https://en.wikipedia.org/w/index.php?search=%s`）
    - `amz`: Amazon 検索 / Amazon Search (`https://www.amazon.co.jp/s?k=%s`)
    - `x`: X (Twitter) 検索 / X Search (`https://x.com/search?q=%s`)
    - `npm`: npm パッケージ検索 / npm Search (`https://www.npmjs.com/search?q=%s`)
    - `mdn`: MDN Web Docs 検索 / MDN Search (`https://developer.mozilla.org/search?q=%s`)
  - ブックマークレット（2 件）:
    - `mdlink`: Markdown リンクをコピー / Copy Markdown Link（現在のページの `[タイトル](URL)` をクリップボードへコピーする `javascript:` コード）
    - `wayback`: Wayback Machine で表示 / Open in Wayback Machine（現在のページ URL を `https://web.archive.org/web/*/` で開く `javascript:` コード）
- **FR-002**: プリセットの初期状態はすべて OFF（未有効化）としなければならない。
- **FR-003**: 設定画面（`preferences.html`）に「プリセット」セクションを設け、各プリセットのチェックボックス、ニックネーム、ローカライズされたタイトル、および URL または動作内容のプレビューを表示して個別に ON / OFF を切り替えられなければならない。
- **FR-004**: プリセットの有効／無効状態は、通常のブックマーク JSON データ（`bookmarks`）には書き込まず、有効化されたプリセット ID の配列（例: `enabledPresets: ["g", "gh"]`）のみを保存することでストレージ容量の消費を最小化しなければならない。
- **FR-005**: Google アカウント同期が OFF の場合はローカルストレージ、同期が ON の場合は同期ストレージ（およびローカルキャッシュ）で有効化プリセット ID リストを保存・管理し、同期の ON / OFF 切り替え（データ移行）時や通常ブックマーク保存時にも有効化プリセット ID リストが失われず正しく同期・保持されなければならない。
- **FR-006**: ポップアップおよびオムニボックスの通常検索時、有効化されているプリセットを固定スコア（`score: 1.0`, `is_pinned: false`）の仮想ブックマークエントリとして検索対象に動的に合成しなければならない。
- **FR-007**: プリセットを使用してページ遷移またはブックマークレット実行を行っても、ストレージ上の `bookmarks` データへのスコア書き込み・更新を行ってはならない。
- **FR-008**: ユーザーが手動で「有効なプリセットと同一ニックネームかつ同一 URL」のブックマークを登録している場合、検索候補に重複表示せずユーザー登録側のエントリのみを表示しなければならない。同一ニックネームで異なる URL が登録されている場合は両方表示し、スコア更新やピン留めされたユーザー登録ブックマークが上位に優先表示されなければならない。
- **FR-009**: ブックマーク一覧画面（`list.html`）のテーブル、JSON エディタ、JSON エクスポート／インポート、および削除コマンド（`:rm`）の対象にはプリセットを含めず、ユーザー登録ブックマークのみを対象としなければならない。
- **FR-010**: ポップアップ起動直後の空白領域に表示される Tips カタログに、設定画面から定番の検索・ブックマークレットのプリセットを有効化できる旨のヒントを 1 件追加しなければならない。
- **FR-011**: 設定画面のプリセットセクション見出し・説明、各プリセットのタイトル・説明、保存通知、および追加する Tip 文言はすべて日本語・英語の双方で定義し、言語切り替え時に再読み込みなしで即時反映されなければならない。

### Key Entities *(include if feature involves data)*

- **プリセット定義（Preset Definition）**: 拡張機能に内蔵される定番ブックマーク／ブックマークレットの静的定義。一意のプリセット ID（兼ニックネーム）、種別（動的 URL またはブックマークレット）、URL（または言語別の URL 解決関数）、および多言語対応のタイトル・説明キーを持つ。
- **有効化プリセット ID リスト（Enabled Preset IDs）**: ユーザーがチェックボックスで ON にしたプリセット ID の文字列配列（例: `["g", "yt", "mdlink"]`）。通常のブックマーク辞書とは独立して保存・同期される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全 12 件のプリセットすべてを有効化した状態でも、保存されるプリセット設定データのサイズが 200 バイト未満（同期ストレージ上限 100KB の 0.2% 未満）に収まる。
- **SC-002**: 設定画面でプリセットのチェックボックスを切り替えた直後、ポップアップおよびオムニボックスの検索候補に遅延や再起動なしで 100% 即座に反映される。
- **SC-003**: プリセットと同一ニックネーム・同一 URL のユーザー登録ブックマークが存在する場合の重複候補発生率が 0% であり、かつスコア `> 1.0` またはピン留め済みの同名ユーザーブックマークが 100% のケースでプリセットより上位に表示される。
- **SC-004**: 日本語・英語の言語設定切り替え時、設定画面のプリセット一覧表示・Wikipedia 検索先ドメイン・ポップアップ Tips のすべてが 100% 選択言語に追従する。

## Assumptions

- プリセットのニックネームはすべて単一階層（スラッシュ `/` を含まない `g`, `yt`, `gh`, `map`, `tr`, `wiki`, `amz`, `x`, `npm`, `mdn`, `mdlink`, `wayback`）であるため、フォルダ階層抽出には影響しない。
- `:open <ニックネーム>` コマンドで有効なプリセットのニックネーム（例: `:open g`）が指定された場合、単一ニックネームオープンとしてプリセットのフォールバック URL（トップページ）を開くことができると自然であるため、検索・オープン解決時にプリセットを参照できるようにする（ただし `:rm` や `:add` の既存ニックネーム一覧には含めない）。
