# Feature Specification: ブックマーク一覧タブの自動更新 (Refresh Bookmark List on Add)

**Feature Branch**: `004-refresh-list-on-add`

**Created**: 2026-11-09

**Status**: Approved

**Input**: User description: "トーストが表示できないページでブックマークを追加すると、ブックマーク一覧が表示され、トーストが表示される。その際、すでにブックマーク一覧が開かれていればそのタブに移動してトーストが表示されるが、ブックマーク一覧はこうしんされてないので、ブックマークがついかされていないようにみえる。ブックマーク一覧を開いていてもちゃんと追加したように見えるようにブックマークが追加されたら一覧を更新して表示するようにする。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 特殊ページでのブックマーク追加時に既存一覧が最新化される (Priority: P1)

ユーザーがChromeの特殊ページ（設定画面や拡張機能一覧など、画面内に直接通知を表示できないページ）でオムニボックスからブックマークを追加した際、すでに別のタブでブックマーク一覧画面を開いている場合がある。このとき、システムは既存の一覧タブをアクティブにして追加完了の通知メッセージを表示するが、同時に一覧の内容も最新の状態に再読み込みされ、たった今追加したブックマークが画面上に即座に表示される。

**Why this priority**:
ブックマークを追加した直後に一覧画面が表示されるにもかかわらず、追加したはずの項目が見当たらないと「登録に失敗したのではないか」とユーザーに強い不安や混乱を与えるため、最優先で解消する必要がある。

**Independent Test**:

1. ブックマーク一覧画面をタブで開いておく。
2. 特殊ページ（例: `chrome://extensions`）に移動する。
3. オムニボックスから新しいブックマークを追加する（`:add <name> <url>`）。
4. 既存の一覧タブが自動的に前面に切り替わり、登録完了通知とともに新しく登録した項目が一覧内に表示されていることを確認できる。

**Acceptance Scenarios**:

1. **Given** ブックマーク一覧画面のタブがすでに開かれている状態で、
   **When** ユーザーが通知表示不可ページから新しいブックマークを登録し、既存の一覧タブへ自動誘導されたとき、
   **Then** 追加完了の通知メッセージが表示されると同時に、一覧データが更新されて追加された項目が表示される。
2. **Given** ブックマーク一覧画面のタブがすでに開かれている状態で、
   **When** 既存の登録内容を上書き・更新する登録が行われたとき、
   **Then** 既存の一覧タブへ切り替わった際に、更新後の内容が反映されて表示される。

---

### User Story 2 - 新規タブで一覧を開いた場合の一貫した表示 (Priority: P2)

ブックマーク一覧画面のタブがまだ開かれていない状態で、通知表示不可ページからブックマークを追加した場合、新しいタブで一覧画面が開かれて通知が表示され、追加されたブックマークが正常に表示される。

**Why this priority**:
既存タブの再利用時だけでなく、新規にタブが開かれた場合でも同様に最新のブックマークが正しく表示される一貫性を担保するため。

**Independent Test**:
ブックマーク一覧タブを閉じた状態で特殊ページからブックマークを追加し、新規に開いたタブで追加項目が正しく表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ブックマーク一覧画面のタブが開かれていない状態で、
   **When** ユーザーが通知表示不可ページからブックマークを追加したとき、
   **Then** 新しいタブで一覧画面が開き、追加完了通知とともに最新のブックマークが表示される。

---

### User Story 3 - 手動で一覧タブに戻った際の一貫性 (Priority: P3)

ユーザーが一覧タブを開いたまま別の通常タブでブックマークを追加・更新し、その後手動で一覧タブに戻ってきた場合でも、一覧が古い状態のまま放置されず、必要に応じて最新情報が反映される。

**Why this priority**:
通知表示不可ページからの自動誘導時だけでなく、日常的なタブ切り替え操作においても表示の食い違いを防ぎ、ユーザー体験の質を向上させるため。

**Independent Test**:
一覧タブを開いたまま通常ページでブックマークを追加し、手動で一覧タブに切り替えた際に一覧が最新化されていることを確認する。

**Acceptance Scenarios**:

1. **Given** 一覧タブを開いた状態で別タブにてブックマークを追加し、
   **When** ユーザーが手動で一覧タブにフォーカスを戻したとき、
   **Then** 画面を手動リロードすることなく最新のブックマーク一覧が確認できる。

---

### Edge Cases

- **大量のブックマークが存在する場合**: 一覧の再読み込みが画面のスクロール位置や検索入力中のフィルタリング状態を不意にリセットしてしまわないこと。
- **通信遅延や保存処理中**: ブックマーク保存が完了する前に一覧再読み込みが走ってしまい、古い状態を取得してしまうタイミング問題が発生しないこと。
- **連続でのブックマーク追加**: 短時間に複数回連続で追加された場合でも、最新の最終状態が正確に一覧へ反映されること。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: システムは、通知表示不可ページからブックマーク一覧タブが再利用（アクティブ化）された際、最新のブックマーク一覧データを自動的に再取得して画面を更新しなければならない (MUST)。
- **FR-002**: システムは、一覧の更新処理中および更新完了後も、ユーザーへの追加完了通知メッセージ（トースト）を欠落させることなく確実に表示しなければならない (MUST)。
- **FR-003**: システムは、ブックマークの新規追加だけでなく、既存項目の更新や削除が反映された場合でも、一覧タブに誘導された際に最新の状態を表示しなければならない (MUST)。
- **FR-004**: システムは、一覧画面の自動更新時に不要な画面全体の白画面リロード（フルリロード）を行わず、データの再バインドによる滑らかな更新を行わなければならない (MUST)。
- **FR-005**: システムは、ユーザーが手動で一覧画面のタブにフォーカスを復帰させた際にも、最新のデータ状態が反映されるよう配慮しなければならない (SHOULD)。

### Key Entities

- **ブックマーク一覧画面 (Bookmark List View)**: 登録済みの全ニックネーム・URL・メタデータをテーブル形式で閲覧・管理する拡張機能の常設UI。
- **完了通知 (Toast Notification)**: ブックマークの追加・更新・削除などの操作結果をユーザーへ一時的に伝えるメッセージ表示。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: ブックマーク一覧タブが既に開かれている状態で特殊ページからブックマークを追加した際、タブがアクティブになってから **1秒以内** に新しく追加されたブックマークが一覧に表示される。
- **SC-002**: 特殊ページからのブックマーク追加時において、登録完了通知の表示成功率 **100%** を維持する。
- **SC-003**: ユーザーが手動でページ全体をリロード（F5 / Cmd+R）する必要性を **0回** に削減する。
- **SC-004**: 一覧画面のデータ再読み込みに伴う画面のチラつきや誤動作（入力フォームの意図しないクリア等）の発生率 **0%** を達成する。

## Assumptions

- 既存の仕様において、特殊ページ（`chrome://` やウェブストア等）では拡張機能のページ内スクリプト注入がブロックされるため、ブックマーク一覧画面（`list.html`）へ遷移・フォーカスして通知を表示するフォールバック設計が存在している。
- ユーザーはオムニボックス（`:add` など）やショートカットからブックマークを追加することが想定されている。
- 一覧画面のデータはブラウザの拡張機能ストレージに安全に永続化されており、データ取得APIを呼び出すことで常に最新データが取得可能である。
