# Feature Specification: 管理画面一覧の列幅固定・URL省略表示およびインライン編集化

**Feature Branch**: `009-list-inline-editing`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "この拡張機能の編集画面をブラッシュアップしたいです。まずニックネーム、タイトルなどの項目の幅が可変なので固定にしてください。またURLの項目は長くなりすぎるので、幅を超える場合は「...」で省略表示するようにしてください。まだ現在編集は「編集」ボタンをおしてポップアップで編集するようになっていますが。ポップアップは廃止し、各項目をクリックするとテキストエリアに変わってそこで編集できるようにしてください。テキストエリアのフォーカスが外れると保存されます。不明点や詳細確認が必要であれば聞いてください。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一覧テーブルの固定幅レイアウトと長い URL の省略表示 (Priority: P1)

ユーザーはブックマーク管理画面の一覧を見る際、登録されているテキストの長さによって列幅が毎回ガタガタと変動せず、常に整った固定幅のレイアウトで項目を素早く視認したい。特に非常に長い URL やブックマークレットが複数行に伸びて一覧全体の見通しが悪くなるのを防ぐため、列幅を超える URL は「...」で省略表示されるようにしたい。

**Why this priority**: 一覧画面の基本的な視認性とレイアウトの安定性は、管理画面を利用するすべてのユーザーの体験に直結するため。長い URL による列崩れや高さの肥大化を防ぐことが、続くインライン編集を快適に使うための前提条件にもなる。

**Independent Test**: 短い文字列と非常に長い文字列（長大な URL やブックマークレット、長いタイトル・ニックネーム）が混在するブックマーク一覧を表示し、データ内容やページング切り替えに関わらず各列の幅が一定に保たれ、幅を超える URL が「...」で省略表示されることを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 短いニックネーム／タイトルと長いニックネーム／タイトルのブックマークが混在する一覧画面、**When** ユーザーが一覧を表示したりページを切り替えたりフォルダ絞り込みを変更したりする、**Then** ニックネーム、タイトル、URL、ピン留め、操作などの各列の幅は登録データの内容に引きずられて伸縮せず、一定の固定幅で表示される。
2. **Given** URL 列の固定幅に収まらない長い URL（または長いブックマークレット）が登録されている状態、**When** 一覧画面を表示する、**Then** URL 文字列が列幅を超えて折り返されたり列をはみ出したりせず、末尾が「...」で省略表示される。
3. **Given** URL が「...」で省略表示されている行、**When** ユーザーが省略された URL 上にマウスカーソルを合わせる、**Then** ツールチップ等で省略前の完全な URL を確認できる。

### User Story 2 - ポップアップ廃止とクリックによるインライン編集・フォーカスアウト保存 (Priority: P1)

ユーザーはブックマークのニックネーム・タイトル・URL を修正したいとき、毎回「編集」ボタンを押してポップアップダイアログを開く手間を省き、一覧表上の変更したい項目を直接クリックするだけでテキストエリアに切り替えて編集し、他の場所をクリックするなどしてフォーカスを外す、または Enter キーを押すだけで即座に保存できるようにしたい。

**Why this priority**: ポップアップダイアログの開閉をなくし、表計算ソフトのようにセル単位で直感的かつ高速に編集・保存できることは、本要望の中核となる機能改善であるため。

**Independent Test**: 一覧テーブルから「編集」ボタンと編集ポップアップが存在しないことを確認し、各編集可能項目をクリックしてテキストエリアが表示されること、内容を変更してフォーカスを外す（または Enter キーを押す）と永続保存され通知が表示されること、Escape キーで編集をキャンセルできること、および不正値入力時に適切にブロック・復元されることを検証できる。

**Acceptance Scenarios**:

1. **Given** ブックマーク管理画面の一覧テーブルが表示されている状態、**When** 操作列を確認する、**Then** 従来のポップアップを開くための「編集」ボタンは廃止されており、ページを開くボタン（通常 URL 時）や削除ボタンなど必要な操作のみが表示される。
2. **Given** 一覧テーブル上の編集可能な項目（ニックネーム、タイトル、URL）が表示されている状態、**When** ユーザーがいずれかの項目をクリックする、**Then** その項目が即座に入力可能なテキストエリアに変わり、元の値が入力された状態で自動的にフォーカスが当たってそのまま文字編集を開始できる。
3. **Given** 項目がテキストエリアに切り替わって内容を修正した状態、**When** ユーザーがテキストエリアの外側をクリックする、Tab キー等でフォーカスを外す、または Enter キー（IME 変換確定時を除く）を押す、**Then** 変更内容が検証・保存されて通常の表示状態に戻り、更新完了の通知が表示される。
4. **Given** 項目がテキストエリアに切り替わって内容を編集している途中、**When** ユーザーが Escape キーを押す、**Then** 編集内容が破棄されて変更前の値のまま通常表示に戻る（保存処理および更新通知は実行されない）。
5. **Given** 項目がテキストエリアに切り替わったが、内容を全く変更しなかった状態、**When** テキストエリアからフォーカスを外す（または Enter キーを押す）、**Then** 不要な更新通知や重複保存を発生させず、そのまま通常の表示状態に戻る。
6. **Given** テキストエリアで必須項目（ニックネームまたは URL）を空にする、あるいは同一ニックネーム内にすでに存在する URL へ変更した状態、**When** フォーカスを外して（または Enter キーで）保存が試みられる、**Then** エラー通知が表示されて不正な保存は阻止され、データは元の有効な値へ安全に維持・復元される。

### User Story 3 - ページを開く操作と動的 URL デフォルト値編集の両立 (Priority: P2)

ユーザーは一覧からインライン編集へ移行した後も、登録先ページを新しいタブで開く操作や、URL に含まれる動的プレースホルダー（`%s`）のデフォルト値編集といった既存機能を失うことなく、直感的に利用し続けたい。

**Why this priority**: 編集ポップアップを廃止しても、既存ユーザーが利用している関連機能（URL 遷移や動的 URL のデフォルト値設定）の退行（デグレード）を防ぐために重要であるため。

**Independent Test**: 通常 URL のブックマークでは「開く」アイコンボタンでページを新しいタブで開けることと URL 文字列クリックで編集できることの両立を、また動的 URL（`%s`）のブックマークでは URL 編集時にあわせてデフォルト値入力欄が表示・保存されることを検証できる。

**Acceptance Scenarios**:

1. **Given** 通常の URL（ブックマークレット以外）が登録されている行、**When** ユーザーが URL 文字列（セル）をクリックするとテキストエリア編集に切り替わり、専用の「開く」アイコンボタンをクリックすると解決済み URL が新しいタブで開く、**Then** 編集操作とページ遷移操作が競合せず意図通りに実行できる。
2. **Given** `%s` を含む動的 URL が登録されている行（または編集中に URL へ `%s` を入力した状態）、**When** ユーザーが URL セルをクリックして編集状態にする、**Then** URL テキストエリアとともに同じセル内に「引数省略時のデフォルト値」入力欄が表示され、URL とデフォルト値の間のフォーカス移動では保存終了せず、編集セル全体からフォーカスが外れたとき（または Enter キー確定時）にあわせて保存される。
3. **Given** 動的 URL から `%s` を削除して通常の URL に変更した状態、**When** 変更を確定して保存する、**Then** 不要になったデフォルト値は自動的にクリアされて保存される。

---

### Edge Cases

- **長い文字列（タイトル・ニックネーム）の固定幅列での表示**: ニックネームやタイトルに非常に長い文字列（スペースを含まない連続英数字や階層パスなど）が入力されている場合でも、列幅が勝手に広がらず枠内に収まって表示（折り返しまたは省略）されること。
- **IME 変換確定時の誤保存防止**: 日本語入力などの IME 変換中に確定目的で Enter キーを押した際には保存確定として扱わず、確定後の通常の Enter キー入力のみを保存トリガーとすること。
- **改行文字の扱い**: テキストエリア上で Enter キーは保存確定として機能し、Shift+Enter 等による改行入力は行わない（貼り付け等に改行が含まれて保存された場合でも表示やデータ整合性が保たれること）。
- **ブックマークレット行での「開く」ボタン**: `javascript:` で始まるブックマークレットの行ではページ遷移できないため、「開く」アイコンボタンは非表示または対象外とすること。
- **編集中の一覧再読み込み抑止**: ユーザーがテキストエリア（またはデフォルト値欄を含む URL 編集セル）でインライン編集を行っている最中に、他タブから戻った際などのバックグラウンド自動再読み込みが走っても、入力中の内容が上書き・リセットされないこと。
- **ブックマークレット（`javascript:`）の編集**: 長大なブックマークレットが登録されている行で URL 項目をクリックした際、省略されていない元の完全なコードがテキストエリアに読み込まれて編集できること。
- **ニックネーム変更によるフォルダ絞り込みへの影響**: フォルダ絞り込み選択中にニックネームを変更して別フォルダへ移動した場合や、同一ニックネーム内の別エントリと URL が重複した場合に、データの整合性が保たれ、空になった旧ニックネームキーが残存しないこと。
- **空白のみ・先頭末尾スラッシュの正規化**: ニックネームの前後に空白や余分なスラッシュが入力された状態で保存された場合も、既存仕様と同じ正規化ルールが適用され、正規化後に空になる場合はエラーとして弾かれること。
- **保存容量上限やストレージエラー発生時**: 同期有効時の容量上限超過などで保存に失敗した場合はエラー通知を表示し、画面上のデータが不整合な状態で確定したように見えないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理画面の一覧テーブルにおける各列（ニックネーム、タイトル、URL、ピン留め、操作等）の幅は、登録されているデータ内容の長さによって動的に伸縮しない固定幅レイアウトとしなければならない。
- **FR-002**: URL 列に表示される文字列（通常 URL およびブックマークレット）は、設定された列幅を超える場合に折り返して行の高さを肥大化させたり列をはみ出したりせず、1 行表示のまま末尾を「...」で省略表示しなければならない。また、省略された文字列についてもマウスオーバー時のツールチップ等で完全な値を確認できる手段を提供しなければならない。
- **FR-003**: 一覧テーブルの各行に配置されていた従来の編集用ポップアップ起動ボタン、およびブックマーク編集用のモーダルダイアログ（ポップアップ）は廃止しなければならない。
- **FR-004**: ユーザーは一覧テーブル上のニックネーム、タイトル、URL の各項目（セル）をクリックすることで、該当項目をインラインのテキストエリアに切り替えて直接編集できなければならない。編集開始時は該当テキストエリアに自動的にフォーカスが移動しなければならない。
- **FR-005**: インライン編集中のテキストエリア（URL セル内でデフォルト値欄を併設している場合はその編集領域全体）からフォーカスが外れたとき、システムは入力内容のバリデーションおよび保存処理を自動的に実行し、通常表示モードへ戻さなければならない。入力値に変更がない場合は不要な保存・通知を行わない。
- **FR-006**: テキストエリア編集中（IME 変換中を除く）に `Enter` キーが押された場合、改行は挿入せず編集内容を確定・保存して通常表示へ戻らなければならない（`Shift+Enter` による改行入力は不要とする）。また、`Escape` キーが押された場合は変更内容を破棄して編集前の値に戻し、保存を行わずに通常表示へ戻らなければならない。
- **FR-007**: インライン保存時のバリデーションにおいて、ニックネームまたは URL が空（空白やスラッシュのみを含む）である場合、あるいは移動・変更先のニックネームに同一 URL がすでに存在する場合は、保存を中断してエラー通知を表示し、値を変更前の有効な状態に戻さなければならない。
- **FR-008**: インライン保存が成功した場合、システムは一覧上の表示（並び順やフォルダ絞り込み結果、ファビコン、動的 URL 判定等）を最新状態に反映し、更新成功をユーザーに通知しなければならない。
- **FR-009**: URL セルは文字列部分を含めクリックでインライン編集モードに移行するものとし、通常の URL（ブックマークレットを除く）を新しいタブで開く操作については、操作列または URL セル横に専用の「開く」アイコンボタンを配置して提供しなければならない。アイコンボタンのクリック時はインライン編集を開始させず、新しいタブで解決済み URL を開かなければならない。
- **FR-010**: 動的 URL（`%s` を含む URL）を編集する際は、URL セルのテキストエリア編集中に同じセル内で URL 入力欄とあわせて「引数省略時のデフォルト値」入力欄を表示し、同時に編集・保存できなければならない。URL から `%s` が削除されて保存された場合は不要なデフォルト値をクリアしなければならない。
- **FR-011**: インライン編集中は、画面へのフォーカス復帰等を契機としたバックグラウンドからの自動データ再読み込みによって編集中の入力状態が失われないよう保護しなければならない。
- **FR-012**: 新規または変更されるすべての UI 文言・ツールチップ（例：「開く」ボタンのツールチップやアクセシビリティラベル等）・通知メッセージは、既存の多言語対応（日本語・英語）に対応し、言語設定変更に追従しなければならない。

### Key Entities *(include if feature involves data)*

- **ブックマーク表示行（Bookmark Row）**: 一覧テーブルの各行が表現するブックマーク情報。ニックネーム、タイトル、URL、引数省略時のデフォルト値、ピン留め状態、使用スコア・日時情報を保持する。
- **インライン編集セッション（Inline Edit State）**: 現在どの行のどの項目（フィールド）がインライン編集中であるか、および編集開始時点の元の識別子（元のニックネーム・元の URL）と編集中テキスト値（URL 編集時はデフォルト値を含む）を一時保持する状態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 長さの異なるブックマークデータ（10 文字未満〜200 文字以上の URL）を表示・ページ切り替えした際、一覧テーブルの各列幅の変動が 0px であり、レイアウトが安定して保たれる。
- **SC-002**: 列幅を超えるすべての URL 項目が 1 行内で「...」により省略表示され、行の高さが過度に膨張しない。
- **SC-003**: ユーザーは任意のブックマーク項目（ニックネーム、タイトル、URL）の修正を「クリック → テキスト修正 → フォーカスアウトまたは Enter」の最短 2 アクション（モーダル開閉操作ゼロ）で完了できる。
- **SC-004**: 誤入力（空値や重複 URL）や Escape キーによるキャンセルを行った場合でも 100% 適切に処理され、既存データが破壊または消失しない。
- **SC-005**: 従来の編集ポップアップで可能だったすべての操作（ニックネーム・タイトル・URL・ピン留め・動的 URL デフォルト値の編集、および一覧からのページ遷移）が、ポップアップ廃止後も欠落なく実行できる。

## Assumptions

- 画面幅が狭い環境（モバイルや狭いウィンドウ幅）でも、テーブル全体の横スクロールや適切な最小幅により固定幅レイアウトが破綻しないようにする。
- タイトル項目が空欄（未設定）の行についても、クリックしてテキストエリアを開きタイトルを追記できるよう、セル全体（空領域を含む）をクリック可能な領域として視覚的に分かりやすく確保する。
- テキストエリアでの編集時は、フォーカスが外れた時点だけでなく Enter キー確定時にも同じ保存処理を経由し、二重保存（Enter による保存と直後の blur による保存の重複実行）が起きないよう排他制御を行う。
- ブックマーク新規登録フォームや JSON 直接編集ダイアログ、フォルダ名変更ダイアログなど、一覧の個別行編集以外のダイアログ機能は本変更の廃止対象には含まない。
- テキストエリアは編集中に入力内容が見やすいよう十分な視認性（セル幅いっぱいの表示と折り返し、適切な高さ）を持ち、保存完了時には既存の更新完了通知と同等のフィードバックを提供する。
