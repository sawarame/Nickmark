# クイックスタート検証ガイド (Quickstart Validation Guide): フォルダ管理と一括オープン

**機能ブランチ**: `002-folder-management`  
**日付**: 2026-11-08  
**対象**: エンドツーエンドの動作検証シナリオおよびテスト手順

---

## 前提条件と環境セットアップ

1. **プロジェクトのビルド**:
   ```bash
   npm run build
   ```
2. **拡張機能のロード**:
   - Google Chrome で `chrome://extensions/` を開く。
   - 「デベロッパー モード」を有効化する。
   - 「パッケージ化されていない拡張機能を読み込む」から本リポジトリの `package/` ディレクトリを選択（または更新アイコンをクリック）。

---

## 検証シナリオ

### シナリオ 1: パス風ニックネームの登録とフォルダ自動認識
1. 任意の Web ページ（例: `https://github.com`）を開き、ショートカットキー `Option + Shift + D`（Windows: `Alt + Shift + D`）を押す。
2. ポップアップでニックネーム欄に `work/gh` と入力して保存する。
3. 別の Web ページ（例: `https://google.com`）で同様に `work/search` を登録する。
4. **期待される結果**:
   - トースト通知が表示され正常に登録される。
   - 既存のデータモデルに破損なく `work/gh`, `work/search` が保存される。

### シナリオ 2: 通常モードでの一括オープン (`nm work/`)
1. Chrome のアドレスバーで `nm` + スペースを入力。
2. `work/` と入力。
3. **期待される結果**:
   - 1行目のデフォルト候補に「📁 work/ の全ブックマークを一括オープン (2タブ)」が表示される。
   - Enter キーを押すと、`https://github.com` と `https://google.com` の 2 つがバックグラウンドタブで開く。

### シナリオ 3: コマンドモードでの一括オープン (`nm :open work`)
1. アドレスバーで `nm :open work` または `nm :o work/` と入力して Enter。
2. **期待される結果**:
   - `work/` 配下の全 URL がバックグラウンドタブで開く。

### シナリオ 4: 管理画面でのフォルダ絞り込みと一括管理
1. アドレスバーで `nm :ls` と入力して管理画面を開く。
2. 画面上部のフォルダフィルタに「work」が表示されていることを確認し、選択する。
3. **期待される結果**:
   - テーブルに `work/gh` と `work/search` のみが絞り込まれて表示される。
   - フォルダ横の「一括オープン」ボタンをクリックすると、配下の URL がすべて開く。
   - フォルダ名変更ダイアログで「office」に変更すると、ニックネームが `office/gh`, `office/search` に一括更新される。
   - フォルダ削除ボタンをクリックし、確認モーダルを承認すると、配下のブックマークがまとめて削除される。

### シナリオ 5: 安全上限（超過確認）と設定変更
1. 設定画面（`nm :prefs`）を開き、「一括オープンの安全上限件数」を `1` に変更して保存する。
2. アドレスバーで `nm office/` と入力して Enter。
3. **期待される結果**:
   - 登録数（2件）が上限（1件）を超えているため、自動では開かず確認プロンプトが表示される。
   - 「開く」を承認すると全タブが開き、「キャンセル」すると開かずに終了する。
