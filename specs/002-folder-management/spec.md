## ユーザーストーリーとテスト検証 *(必須)*

### ユーザーストーリー 1 - パス風ニックネームによるフォルダ一括オープン (優先度: P1)

ユーザーはアドレスバー（オムニボックス）でフォルダ名を指定し、そのフォルダに属する複数のブックマークを一斉にバックグラウンドタブで開くことができる。

- **この優先度である理由**: 目的のサイト群を一瞬で呼び出して作業環境を展開するという、本機能の最重要・中核価値であるため。
- **独立テスト方法**: 
  - `work/gh` と `work/jira` を登録した状態で、オムニボックスで `nm work/` と入力して Enter を押す、または `nm :open work/` を実行し、両方のタブがバックグラウンドで開くことを確認する。
- **受入シナリオ**:
  1. **Given** ニックネーム `work/gh` と `work/jira` が登録されている  
     **When** オムニボックスで `nm work/` と入力する  
     **Then** 最上位候補に「📁 work/ の全ブックマークを一括オープン (2タブ)」が表示され、Enterキーを押すと両方のURLが新規バックグラウンドタブで開く。
  2. **Given** ニックネーム `work/gh` と `work/jira` が登録されている  
     **When** オムニボックスで `nm :open work` または `nm :open work/`（短縮系 `:o` も同様）を実行する  
     **Then** 配下の2つのURLが新規バックグラウンドタブで開く。
  3. **Given** ニックネーム `work/gh` と `work/sub/repo` が登録されている  
     **When** `nm work/` で一括オープンを実行する  
     **Then** サブフォルダ `work/sub/` を含む配下の全URL（再帰的）が開く。
  4. **Given** 同一フォルダ内に同一URLのエントリが複数存在する  
     **When** フォルダ一括オープンを実行する  
     **Then** 重複URLは自動除外され、1タブのみ開く。

### ユーザーストーリー 2 - 安全上限とユーザー確認機構 (優先度: P2)

大量のブックマークが所属するフォルダを一括オープンする際、ブラウザのフリーズや誤爆を防ぐため、安全上限件数（デフォルト: 20件、設定で変更可能）を超過した場合はユーザーに確認を求める。

- **この優先度である理由**: 意図せず数十〜数百タブが一気に開きブラウザがクラッシュ・ハングアップする重大事故を確実に防止するため。
- **独立テスト方法**:
  - 上限が20件の状態で21件以上のURLを含むフォルダを開こうとした際、自動では開かず確認プロンプトが表示され、「キャンセル」時は開かず、「開く」を選択した時のみ開くことを確認する。設定画面で上限値を変更できることを確認する。
- **受入シナリオ**:
  1. **Given** フォルダ配下の対象URL数が設定上限（例: 20件）以下である  
     **When** 一括オープンを実行する  
     **Then** 確認なしで自動的にすべてのURLが開く。
  2. **Given** フォルダ配下の対象URL数が設定上限（例: 20件）を超えている（例: 25件）  
     **When** オムニボックスから一括オープンを実行する  
     **Then** タブは自動で開かず、現在のアクティブタブ上に確認プロンプト（ダイアログ/トースト）が表示され、ユーザーが承認した場合にのみ全25タブが開く。
  3. **Given** 設定画面（Preferences）を開いている  
     **When** 「一括オープンの安全上限件数」を変更して保存する  
     **Then** 新しい上限値が即座に反映され、以降の一括オープン判定で使用される。

### ユーザーストーリー 3 - 管理画面（list.html）でのフォルダ絞り込みと一括管理 (優先度: P2)

管理画面（ダッシュボード）で、登録されたニックネームから自動抽出されたフォルダ一覧を使ってブックマークをフィルタリングでき、フォルダ単位での一括オープン、一括リネーム、一括削除が行える。

- **この優先度である理由**: 大量のブックマークを視覚的に整理・保守し、フォルダ単位のメンテナンス性を担保するため。
- **独立テスト方法**:
  - 管理画面のフォルダタブ/ドロップダウンで「work」を選択すると、`work/*` のブックマークのみがテーブルに表示され、フォルダ横の一括オープンボタンで全タブが開くことを確認する。また、フォルダ名リネームや一括削除が正常に動作することを確認する。
- **受入シナリオ**:
  1. **Given** `work/gh` と `personal/blog` が登録されている  
     **When** 管理画面を開く  
     **Then** フォルダフィルタに「すべて」「work」「personal」が表示される。
  2. **Given** フォルダフィルタで「work」を選択している  
     **When** 「一括オープン」ボタンをクリックする  
     **Then** `work/` 配下のURLがバックグラウンドタブで開く（上限超過時は確認モーダル表示）。
  3. **Given** フォルダフィルタまたは管理メニューで「work」のフォルダ名変更を選択し、新しい名前「office」を入力して保存する  
     **When** リネームを実行する  
     **Then** `work/gh` が `office/gh` に一括更新され、ストレージに保存される。
  4. **Given** 「work」フォルダの一括削除を選択する  
     **When** 警告確認ダイアログで「削除」を承認する  
     **Then** `work/` 配下のすべてのブックマークが安全に削除される。

### ユーザーストーリー 4 - クイック登録時のフォルダ補完と入力支援 (優先度: P3)

ポップアップ登録ダイアログ（`popup.html`）や管理画面の新規登録フォームで、既存のフォルダ名が自動サジェストされ、素早くフォルダ配下のニックネームを登録できる。

- **この優先度である理由**: 登録時のキーストロークを削減し、タイポによるフォルダ名のブレ（例: `work/` と `works/`）を防ぐため。
- **独立テスト方法**:
  - ポップアップでニックネーム入力欄に `w` と入力した際、既存フォルダ `work/` が候補に表示され、選択すると `work/` が補完入力されることを確認する。
- **受入シナリオ**:
  1. **Given** フォルダ `work/` に属するブックマークが存在する  
     **When** ポップアップでニックネーム欄に `wo` と入力する  
     **Then** オートコンプリート候補に `work/` が表示され、Tabキーやクリックで `work/` を補完できる。
  2. **Given** ニックネーム欄に `project/task` と入力して保存する  
     **When** 保存を実行する  
     **Then** `project/task` として登録され、次回のフォルダ抽出対象に `project` が自動認識される。

## エッジケースと異常系

- **同名ニックネームとフォルダの衝突**:
  - `work` という単体ニックネームと、`work/gh` という階層ニックネームが両方存在する場合、`nm work` では単体ニックネーム `work` が優先表示され、`nm work/`（末尾スラッシュ）ではフォルダ一括オープンが最上位候補となる。
- **対象URLが0件（ブックマークレットのみ）の場合**:
  - フォルダ配下にブックマークレット（`javascript:`）しか存在しない場合、タブ起動は行わず、スキップされた旨をトースト通知する。
- **動的URL（`%s`）が含まれる場合**:
  - フォルダ一括オープン時は引数が存在しないため、設定されたデフォルト値（`default_value`）またはオリジンURLへフォールバックして開く。
- **同期ストレージ容量制限（100KB）**:
  - リネームや一括処理時も、既存の 2000 文字チャンク分割（`sync_data_N`）および 100KB 容量チェックを維持し、容量超過時はエラーを送出する。

## 機能要件一覧 *(必須)*

### データ構造と解釈
- **FR-001**: システムは既存のデータ構造 `Record<string, BookmarkEntry[]>` を変更せず、ニックネーム文字列内に含まれるスラッシュ `/` を階層区切り（フォルダ）として動的に解釈しなければならない（MUST）。
- **FR-002**: システムはスラッシュ区切りの親階層（例: `a/b/c` における `a` および `a/b`）を再帰的にフォルダ構造として認識しなければならない（MUST）。

### オムニボックス & 一括オープン
- **FR-003**: ユーザーがオムニボックスで `nm <フォルダ名>/` と入力した際、最上位候補にフォルダ配下の一括オープン候補を表示し、Enterキーでバックグラウンドタブ群を開かなければならない（MUST）。
- **FR-004**: ユーザーがオムニボックスで `nm <フォルダ名>` と入力した際、配下の個別候補を優先しつつ、候補リスト内にフォルダ一括オープン候補を提示しなければならない（MUST）。
- **FR-005**: ユーザーが `:open <フォルダ名>` または `:open <フォルダ名>/`（短縮 `:o` を含む）を実行した際、配下の全ブックマークを一括オープンしなければならない（MUST）。
- **FR-006**: 一括オープン処理は同一URLの重複を自動排除し、ブックマークレットはスキップし、動的URLはフォールバックURLで開かなければならない（MUST）。
- **FR-007**: 一括オープンされた各ブックマークの `score` および `last_used_at` を正常に更新しなければならない（MUST）。

### 安全上限と確認
- **FR-008**: システムは一括オープン対象のURL数が設定上限件数（デフォルト: 20件）を超える場合、自動オープンを中断し、ユーザーに確認を求めなければならない（MUST）。
- **FR-009**: 設定画面（Preferences）において、ユーザーが「一括オープンの安全上限件数（1〜100件、デフォルト: 20件）」を設定・保存できるようにしなければならない（MUST）。
- **FR-010**: 安全上限設定値は `chrome.storage.local` に保存され、デバイス固有設定として管理されなければならない（MUST）。

### 管理画面 UI
- **FR-011**: 管理画面（`src/List.vue`）上部に、登録ニックネームから抽出されたフォルダ一覧による絞り込みフィルタ（PrimeVue `Select` または `Tabs`）を提供しなければならない（MUST）。
- **FR-012**: 選択中のフォルダ配下の全ブックマークを一括で開くボタンを管理画面上に提供しなければならない（MUST）。
- **FR-013**: 管理画面上でフォルダ名を一括リネーム（全対象ニックネームのプレフィックス置換）する機能を提供しなければならない（MUST）。
- **FR-014**: 管理画面上で対象フォルダ配下の全ブックマークを一括削除する機能（確認ダイアログ付き）を提供しなければならない（MUST）。

### 登録ダイアログ UI
- **FR-015**: ポップアップ（`src/Popup.vue`）および管理画面のニックネーム入力欄において、既存のフォルダ名プレフィックス（`フォルダ名/`）を自動サジェスト補完候補に含めなければならない（MUST）。

### 多言語対応
- **FR-016**: 本機能に関するすべての UI テキスト、トースト通知、オムニボックス説明文、設定項目は、`package/_locales/ja/messages.json` および `package/_locales/en/messages.json` に完全定義し、`src/i18n.ts` 経由で取得しなければならない（MUST）。
