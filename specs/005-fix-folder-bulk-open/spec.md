# 機能仕様書: フォルダ一括オープン時における同名単体ブックマークの除外 (Exclude Standalone Bookmarks from Folder Bulk Open)

**機能ブランチ**: `005-fix-folder-bulk-open`  
**作成日**: 2026-11-10  
**ステータス**: Draft  
**入力**: ユーザー要件「フォルダを一括で開こうとするとフォルダ名と同じニックネームのブックマークも開いてしまう。フォルダに登録していないブックマークは一括で開く対象外にして欲しい。」

---

## ユーザーストーリーとテスト検証 *(必須)*

### ユーザーストーリー 1 - フォルダ一括オープン時に同名単体ブックマークを除外 (優先度: P1)

ユーザーがオムニボックス（アドレスバー）や管理画面からフォルダの一括オープンを実行した際、そのフォルダ配下に登録されているブックマークのみが開き、フォルダ名と同名の単体ブックマーク（未分類ブックマーク）は開かれない。

- **この優先度である理由**: フォルダに所属していない単体ブックマークが意図せず一括オープンに巻き込まれる不具合を解消し、ユーザーが意図したフォルダ配下のタブ群のみを安全に開くため。
- **独立テスト方法**:
  - 単体ニックネーム `work`（URL: A）と、フォルダ内ニックネーム `work/mail`（URL: B）、`work/doc`（URL: C）を登録する。
  - オムニボックスで `nm work/` を入力して Enter を押す、または `:open work/`（もしくは `:open work`）を実行する。
  - URL B と URL C のみが新規タブで開き、URL A は開かないことを確認する。
  - 管理画面（`list.html`）で「work」フォルダを選択し、「一括オープン」を実行した際も同様に URL B と URL C のみが開くことを確認する。
- **受入シナリオ**:
  1. **Given** 単体ニックネーム `work` とフォルダ配下ニックネーム `work/mail` が登録されている  
     **When** オムニボックスで `nm work/` と入力して一括オープンを実行する  
     **Then** `work/mail` のみが開き、単体の `work` は開かない。
  2. **Given** 単体ニックネーム `work` とフォルダ配下ニックネーム `work/mail` が登録されている  
     **When** オムニボックスで `:open work/` を実行する  
     **Then** `work/mail` のみが開き、単体の `work` は開かない。
  3. **Given** 単体ニックネーム `work` とフォルダ配下ニックネーム `work/mail` が登録されている  
     **When** 管理画面の「一括オープン」ボタンを実行する  
     **Then** `work/mail` のみが開き、単体の `work` は開かない。
  4. **Given** フォルダ配下ブックマークのみが登録されており、同名の単体ニックネームが存在しない（例: `tool/calc` のみ）  
     **When** `tool` フォルダの一括オープンを実行する  
     **Then** 従来通り `tool/calc` が正常に開く。

---

### ユーザーストーリー 2 - 管理画面におけるフォルダ管理の整合性確保 (優先度: P2)

管理画面（ダッシュボード）で特定のフォルダを選択した際、フォルダ配下に登録されたブックマークのみがフィルタリングされ、同名単体ブックマークが誤って一覧に混入したり、フォルダのリネームや一括削除に巻き込まれたりしない。

- **この優先度である理由**: フォルダ操作の一貫性を保ち、ユーザーが意図しない単体ブックマークの誤削除や誤リネームによるデータ破損・混乱を防止するため。
- **独立テスト方法**:
  - 単体ニックネーム `dev` と、フォルダ内ニックネーム `dev/repo` を登録する。
  - 管理画面でフォルダ「dev」を選択した際、一覧テーブルに `dev/repo` のみが表示され `dev` は表示されないことを確認する。
  - 「未分類（ルート）」を選択した際に `dev` のみが表示されることを確認する。
  - 「dev」フォルダのリネームや削除を行った際、`dev` 単体ブックマークには影響が及ばないことを確認する。
- **受入シナリオ**:
  1. **Given** 単体ニックネーム `dev` とフォルダ配下ニックネーム `dev/repo` が登録されている  
     **When** 管理画面のフォルダフィルタで「dev」を選択する  
     **Then** 一覧テーブルには `dev/repo` のみが表示され、単体ニックネーム `dev` は表示されない。
  2. **Given** 単体ニックネーム `dev` が登録されている  
     **When** 管理画面のフォルダフィルタで「未分類（ルート）」を選択する  
     **Then** 一覧テーブルに単体ニックネーム `dev` が表示される。
  3. **Given** 単体ニックネーム `dev` とフォルダ配下ニックネーム `dev/repo` が登録されている  
     **When** 管理画面で「dev」フォルダの名前を「development」に変更する  
     **Then** `dev/repo` は `development/repo` にリネームされるが、単体ニックネーム `dev` はそのまま維持される。
  4. **Given** 単体ニックネーム `dev` とフォルダ配下ニックネーム `dev/repo` が登録されている  
     **When** 管理画面で「dev」フォルダの削除を実行する  
     **Then** `dev/repo` は削除されるが、単体ニックネーム `dev` は削除されずに残る。

### エッジケース

- **フォルダ配下にブックマークが存在せず、同名単体ニックネームのみが存在する場合**:
  - 例: `hobby` という単体ニックネームのみが存在し、`hobby/*` は存在しない。
  - この場合 `hobby` はフォルダではないため、`nm hobby/` やフォルダ一括オープンを実行しても対象フォルダなしのエラー案内となり、単体ニックネーム `hobby` が誤って開くことはない。
- **多階層フォルダ（サブフォルダ）と同名ニックネームが存在する場合**:
  - 例: 単体ニックネーム `a/b` と `a/b/c` が存在する場合。
  - フォルダ `a` を一括オープンした場合は、`a/b` も `a/` 配下のエントリであるため開く対象となる。
  - 一方、フォルダ `a/b` を一括オープンした場合は、単体 `a/b` は除外され、その配下である `a/b/c` のみが開く。
- **フォルダ配下の対象URLが0件（ブックマークレットのみ）の場合**:
  - フォルダ配下にブックマークレットしか存在せず、同名単体ブックマークが存在していても、同名単体ブックマークは開かず、開く対象URLがない旨の通知を行う。

## 要件一覧 *(必須)*

### 機能要件 (Functional Requirements)

- **FR-001**: システムは、フォルダの一括オープン処理において、指定されたフォルダの配下に属するブックマーク（階層区切り記号 `/` で始まる配下エントリ）のみを開く対象とし、フォルダ名と完全一致する単体ブックマーク（未分類エントリ）を開く対象から完全に除外しなければならない（MUST）。
- **FR-002**: システムは、オムニボックスからの末尾スラッシュ指定（例: `nm <フォルダ名>/`）によるフォルダ一括オープン時、フォルダ名と同名の単体ブックマークを開く対象に含めてはならない（MUST）。
- **FR-003**: システムは、オムニボックスの `:open <フォルダ名>/` コマンドによるフォルダ一括オープン時、フォルダ名と同名の単体ブックマークを開く対象に含めてはならない（MUST）。
- **FR-004**: システムは、管理画面（`List.vue`）の「一括オープン」ボタンによる実行時、フォルダ名と同名の単体ブックマークを開く対象に含めてはならない（MUST）。
- **FR-005**: システムは、管理画面のフォルダ絞り込みフィルタにおいて、選択されたフォルダ配下に属するブックマークのみを表示し、フォルダ名と同名の単体ブックマークは含めてはならない（MUST）。
- **FR-006**: システムは、管理画面のフォルダ一括リネーム機能において、フォルダ配下に属するブックマークのみをリネーム対象とし、フォルダ名と同名の単体ブックマークをリネーム対象から除外しなければならない（MUST）。
- **FR-007**: システムは、管理画面のフォルダ一括削除機能において、フォルダ配下に属するブックマークのみを削除対象とし、フォルダ名と同名の単体ブックマークを削除対象から除外しなければならない（MUST）。
- **FR-008**: システムは、フォルダ配下にブックマークが存在しない場合（同名の単体ブックマークのみが存在する場合を含む）、フォルダが存在しない、または開く対象URLがない旨の適切な案内を表示しなければならない（MUST）。

### 主要エンティティ (Key Entities)

- **フォルダ (Folder)**:
  - ニックネームのパス区切り（`/`）の親階層によって動的に認識される仮想グループ。
  - 属性: フォルダパス（例: `work`）、表示名（例: `work`）、所属する配下ブックマークのニックネーム一覧（例: `work/mail`, `work/doc`）。
  - 制約: フォルダパスと完全一致する単体ニックネーム（例: `work`）はフォルダ自身であり、フォルダ配下の子エントリとはみなさない。
- **ブックマークエントリ (BookmarkEntry)**:
  - ニックネーム、URL、タイトル、スコアなどの情報を持つブックマーク。
  - ルート（未分類）ブックマーク: スラッシュを含まない単体ニックネーム（例: `work`）。
  - フォルダ所属ブックマーク: フォルダパスをプレフィックスとしてスラッシュで区切られたニックネーム（例: `work/mail`）。

## 成功基準 *(必須)*

### 測定可能な成果 (Measurable Outcomes)

- **SC-001**: フォルダ名と同名の単体ブックマークが存在する条件下において、フォルダ一括オープンを実行した際に単体ブックマークが誤って開く発生率が 0% であること。
- **SC-002**: 管理画面でのフォルダ絞り込み表示、一括オープン、リネーム、削除の各操作において、単体ブックマークが誤って対象に含まれる発生率が 0% であること。
- **SC-003**: フォルダ配下に属する正規のブックマークに対する一括オープン機能（タブ起動、重複排除、安全上限確認）がリグレッションなく 100% 正常に動作すること。
- **SC-004**: 単体ブックマーク単独でのオムニボックス検索・遷移・`:open` 起動が一切損なわれず、独立して正常に動作すること。

---

## 前提条件と想定 (Assumptions)

- **階層モデル**: Nickmark におけるフォルダは独立した実体テーブルではなく、ニックネーム文字列内のスラッシュ `/` に基づいて動的に導出される設計（既存仕様）を継続する。
- **未分類エントリの定義**: スラッシュを含まないニックネーム（例: `work`）は、同名のフォルダ（例: `work/`）が存在する場合でも、常に未分類（ルート）のエントリとして扱われる。
- **既存データへの影響**: 本機能改修は既存の保存データ構造（JSON）を変更せず、フィルタリングおよび対象収集ロジックの適正化によって実現される。
